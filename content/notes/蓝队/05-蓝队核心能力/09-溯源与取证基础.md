## 1. 概念区分

| 概念 | 目标 | 产出 |
|---|---|---|
| 应急响应 | 控制与恢复 | 处置报告 |
| 数字取证（Forensics） | 还原事实、保全证据 | 取证报告、证据链 |
| 溯源（Tracing） | 追踪攻击来源与路径 | 攻击链、时间线 |
| 归因（Attribution） | 判断攻击者身份/组织 | 归因结论（谨慎） |

> 蓝队做的是「基于证据的溯源」，不是「人肉攻击者」。归因需要多源情报与专业能力，且存在误判与法律风险。

---

## 2. 取证原则

1. **合法授权**：取证范围、数据、人员都要有授权。
2. **证据完整性**：不修改原始证据，计算哈希。
3. **证据链**：记录谁、何时、何地、如何采集、存放、交接。
4. **易失优先**：先内存、网络、进程，后磁盘、备份。
5. **可复现**：记录工具、版本、命令、参数。
6. **最小影响**：不影响业务，不破坏证据。
7. **隐私保护**：个人信息最小化。

---

## 3. 易失性顺序（RFC 3227）

```text
CPU 寄存器/缓存
  → 内存（RAM）
  → 交换分区/Pagefile
  → 网络连接/ARP/路由
  → 运行进程
  → 临时文件
  → 磁盘
  → 远程日志/监控数据
  → 备份/归档
  → 物理介质
```

> 先采集最容易消失的数据。

## 4. 主机取证

### 4.1 内存

采集工具：

- WinPmem
- Magnet RAM Capture
- LiME（Linux）
- AVML（Linux）

分析：

- Volatility 3
- MemProcFS

可提取：

- 进程与命令行
- 网络连接
- 加载模块
- 注入代码
- 凭据/哈希
- 注册表
- 文件缓存
- 恶意软件配置

### 4.2 磁盘

采集：

- FTK Imager
- dd/dcfldd（Linux）
- 写保护器

分析：

- Autopsy
- The Sleuth Kit
- X-Ways（商业）
- EnCase（商业）

关注：

- 文件系统与时间戳
- 删除文件恢复
- 分区与未分配空间
- 文件哈希
- 浏览器历史
- 下载记录
- USB 使用
- 回收站

### 4.3 Windows 关键痕迹

| 痕迹 | 位置 | 价值 |
|---|---|---|
| 事件日志 | `C:\Windows\System32\winevt\Logs` | 登录、进程、服务、任务 |
| Prefetch | `C:\Windows\Prefetch` | 程序执行 |
| Amcache | `C:\Windows\AppCompat\Programs\Amcache.hve` | 程序执行 |
| ShimCache | 注册表 | 程序兼容性缓存 |
| UserAssist | 注册表 | 用户执行程序 |
| RecentDocs | 注册表 | 最近文档 |
| Jump Lists | `AppData\Roaming\Microsoft\Windows\Recent\AutomaticDestinations` / `CustomDestinations` | 最近文件 |
| Shellbags | 注册表 | 文件夹访问 |
| USB | 注册表 `USBSTOR` | USB 设备 |
| SRUM | `C:\Windows\System32\sru` | 网络/应用使用 |
| 计划任务 | `C:\Windows\System32\Tasks` | 持久化 |
| 服务 | 注册表 | 持久化 |
| WMI | `C:\Windows\System32\wbem\Repository` | 持久化 |
| 浏览器 | 各浏览器目录 | 访问历史 |
| 回收站 | `C:\$Recycle.Bin` | 删除文件 |
| 跳转列表/最近 | 用户目录 | 用户行为 |

### 4.4 Linux 关键痕迹

| 痕迹 | 位置 |
|---|---|
| 登录 | `/var/log/auth.log`、`secure`、`wtmp`、`btmp` |
| 命令 | `~/.bash_history`、auditd |
| 服务 | `/etc/systemd/system`、`/lib/systemd/system` |
| 计划任务 | `/etc/crontab`、`/etc/cron.*`、`/var/spool/cron` |
| SSH | `~/.ssh/authorized_keys`、`known_hosts` |
| 用户 | `/etc/passwd`、`/etc/shadow`、`/etc/group` |
| Web | `/var/log/nginx`、`/var/log/apache2` |
| 内核模块 | `lsmod`、`/lib/modules` |
| 文件 | 时间戳、inode、SUID |
| 容器 | `/var/lib/docker`、K8s 日志 |

## 6. 时间线分析

### 6.1 目的

把主机、网络、身份、应用事件按时间排序，还原攻击过程。

### 6.2 步骤

1. 收集各数据源时间戳。
2. 统一时区（UTC）。
3. 标准化字段。
4. 合并排序。
5. 标注关键事件。
6. 识别时间缺口/矛盾。
7. 形成攻击链。

### 6.3 工具

- plaso/log2timeline
- Timesketch
- Excel/pandas（小规模）
- SIEM

### 6.4 注意事项

- 时间戳可被篡改
- 不同系统时钟不同步
- 时区转换错误
- 日志缺失
- 文件系统时间语义不同

## 7. 证据链与报告

### 7.1 证据链记录

```text
证据编号：
描述：
来源：
采集人：
采集时间：
采集地点：
采集工具/版本：
哈希（SHA256）：
存放位置：
交接记录：
```

### 7.2 报告结构

```text
1. 摘要
2. 授权与范围
3. 证据与方法
4. 时间线
5. 攻击链分析
6. 影响评估
7. 结论
8. 附件（哈希、日志、截图）
```

## 8. 反取证

攻击者可能：

- 删除/清除日志（1102、wevtutil）
- 修改时间戳（Timestomping）
- 删除文件/安全擦除
- 隐藏进程/文件（Rootkit）
- 禁用审计
- 使用内存/无文件
- 伪造账号/日志

应对：

- 外部日志副本
- 日志完整性校验
- 内存取证
- 文件系统底层分析
- 多源交叉验证
- 威胁狩猎

> 详见 [反取证与痕迹清理](../08-威胁框架与攻防对抗/08-反取证与痕迹清理.md)。

## 9. 归因与法律边界

- 归因需要多源情报、TTP、基础设施、语言/时区等综合分析
- 攻击者可伪装来源（代理、跳板、伪造标志）
- 归因结论要标注置信度
- 不要公开指控未经证实的主体
- 不要「反黑」或入侵攻击者系统
- 发现犯罪线索应通过法务与执法机关处理

## 11. 实操

1. 用 FTK Imager 制作一个 U 盘/虚拟机磁盘镜像。
2. 用 Autopsy 分析镜像，找出浏览器历史与最近文件。
3. 用 Volatility 分析内存样本（公开样本）。
4. 用 KAPE 采集 Windows 痕迹。
5. 用 plaso 生成时间线并导入 Timesketch。
6. 用 Wireshark 分析一个恶意流量样本。
7. 写一份包含证据链的取证报告。

> 仅使用公开样本或自己的实验环境。
