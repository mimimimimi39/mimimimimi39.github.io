## 1. 通用处置流程

```text
接警 → 确认 → 隔离 → 取证 → 排查 → 清除 → 恢复 → 复盘
```

| 阶段 | 关键动作 | 注意事项 |
|---|---|---|
| 接警 | 记录来源、时间、现象 | 不遗漏任何线索 |
| 确认 | 验证是否真实事件 | 避免误报浪费资源 |
| 隔离 | 网络隔离、账号禁用 | 保留证据与业务沟通 |
| 取证 | 内存、磁盘、日志、流量 | 先易失后持久 |
| 排查 | 入口、持久化、横向、外传 | 多源交叉 |
| 清除 | 删文件、修漏洞、重置凭据 | 防复发 |
| 恢复 | 恢复业务、验证 | 持续监控 |
| 复盘 | 时间线、根因、改进 | 更新规则与流程 |

> 原则：**先控制，后取证；先取证，后清除；先修复，后恢复。**

## 2. 勒索软件

### 2.1 识别

- 文件被加密、扩展名变化
- 勒索说明（README、桌面壁纸）
- 业务系统无法访问
- 大量文件修改/删除
- 卷影副本被删除
- 备份被攻击

### 2.2 立即处置

1. **隔离受感染主机**（断网，不关机）。
2. 禁用相关账号，重置高权限凭据。
3. 检查备份是否可用、是否被感染。
4. 保存样本、日志、内存。
5. 通知管理层、法务、业务。
6. 不要支付赎金（不代表一定能恢复，且可能助长犯罪）。
7. 评估是否扩散到其他主机/域控。

### 2.3 排查

- 入口：钓鱼、RDP 爆破、VPN、漏洞、供应链
- 传播：SMB、RDP、共享、域管
- 持久化：服务、计划任务、启动项
- 权限：域管、备份账号
- 数据是否被窃取（双重勒索）

### 2.4 清除与恢复

- 重装受影响主机（不要只删文件）
- 修复入口
- 重置所有相关凭据（含 krbtgt 两次）
- 从离线备份恢复
- 验证备份完整性
- 持续监控

### 2.5 检测线索

- 大量文件重命名/加密
- 卷影副本删除（`vssadmin delete shadows`）
- 备份服务停止
- 异常 SMB/RDP 横向
- 勒索说明文件
- 异常进程/命令行

## 3. 挖矿

### 3.1 识别

- CPU/GPU 占用高
- 风扇狂转、机器变慢
- 异常外连矿池
- 异常进程（伪装 `kworker`、`systemd`）
- 云上异常计费

### 3.2 排查

**Linux**：

```bash
top
ps aux --sort=-%cpu | head
ss -tulnp
crontab -l
systemctl list-units --type=service
find /tmp /var/tmp /dev/shm -type f -executable
```

**Windows**：

```powershell
Get-Process | Sort-Object CPU -Descending | Select -First 20
Get-CimInstance Win32_Process | Select ProcessId,ParentProcessId,Name,CommandLine
Get-NetTCPConnection
Get-ScheduledTask
```

### 3.3 处置

- 隔离主机
- 结束恶意进程
- 删除恶意文件/计划任务/服务
- 修复入口（弱口令、漏洞、Redis 未授权等）
- 重置凭据
- 加强监控

## 4. Webshell

### 4.1 识别

- Web 目录异常脚本
- 访问日志异常 POST
- Web 进程拉起 shell
- 站点被篡改
- 异常外连

### 4.2 排查

- Web 日志：上传、访问、参数、UA
- 文件：新增/修改脚本、时间、内容、哈希
- 进程：`w3wp.exe`/`php-fpm`/`java` 子进程
- 网络：外连、下载
- 持久化：服务、计划任务、账号
- 横向：内网连接

### 4.3 处置

- 隔离/下线
- 保存日志与样本
- 删除 Webshell
- 修复上传/注入漏洞
- 重置 Web 账号/数据库凭据
- 检查数据是否泄露
- 恢复并监控

---

## 5. 钓鱼邮件

### 5.1 识别

- 发件人异常/仿冒
- 紧急/诱导性话术
- 附件（宏、LNK、ISO、HTML、压缩包）
- 链接（短链、仿冒域名）
- 二维码
- 与业务不符

### 5.2 排查

- 邮件头：SPF/DKIM/DMARC、发件 IP、Return-Path
- 附件哈希、沙箱
- URL 情报、沙箱
- 谁点击/谁输入凭据
- 终端是否执行
- 账号是否异常登录

### 5.3 处置

- 删除/隔离邮件
- 封禁发件人/域名/IP
- 通知用户
- 重置受影响账号
- 终端排查
- 加检测规则

---

## 6. 账号失陷

### 6.1 识别

- 异常地点/时间登录
- MFA 异常/被关闭
- 异常权限变更
- 异常邮件发送
- 异常 API 调用
- 用户报告

### 6.2 排查

- 登录日志（4624/4625/4768/4769）
- MFA 日志
- 邮箱规则/转发
- OAuth 应用授权
- 会话/Token
- 权限与组成员
- 关联主机

### 6.3 处置

- 禁用账号/撤销会话
- 重置密码
- 重新注册 MFA
- 撤销异常 OAuth 授权
- 检查邮箱规则
- 排查主机
- 通知相关方

---

## 7. 数据泄露

### 7.1 识别

- DLP 告警
- 异常大流量上传
- 数据库大批量查询
- 云存储公开
- 暗网/情报发现
- 用户报告

### 7.2 排查

- 数据访问日志
- 数据库查询日志
- 代理/流量
- 终端外设/USB
- 邮件/网盘
- 云存储权限
- 内部人员

### 7.3 处置

- 阻断外传
- 保存证据
- 评估数据范围与敏感度
- 通知法务/合规
- 按法规通报
- 修复权限/配置
- 加强 DLP/监控

---

## 8. 蠕虫/横向扩散

### 8.1 识别

- 多台主机同时异常
- 445/135/139 大量连接
- 共享扫描
- 账号异常登录
- 服务创建
- 安全设备告警

### 8.2 处置

- 快速隔离网段
- 阻断横向端口
- 禁用相关账号
- 排查入口
- 打补丁/加固
- 全网扫描
- 恢复与监控

---

## 9. 云上事件

### 9.1 识别

- 异常 API 调用
- AccessKey 泄露
- 异常资源创建（挖矿）
- 对象存储公开
- 安全组开放
- 账单异常

### 9.2 处置

- 禁用/轮换密钥
- 收紧 IAM/安全组
- 隔离实例
- 检查后门账号/角色
- 保存云审计日志
- 修复配置
- 开启告警

## 10. Windows 应急排查命令

> 建议以管理员权限运行；先只读采集，再处置。

```powershell
# 账号
Get-LocalUser
Get-LocalGroupMember -Group "Administrators"

# 进程
Get-CimInstance Win32_Process | Select ProcessId,ParentProcessId,Name,CommandLine,ExecutablePath

# 网络
Get-NetTCPConnection -State Established

# 服务
Get-CimInstance Win32_Service | Select Name,State,StartName,PathName

# 计划任务
Get-ScheduledTask

# 启动项
Get-CimInstance Win32_StartupCommand

# 登录日志
Get-WinEvent -FilterHashtable @{LogName="Security"; Id=4624} -MaxEvents 20
Get-WinEvent -FilterHashtable @{LogName="Security"; Id=4625} -MaxEvents 20

# 日志清除
Get-WinEvent -FilterHashtable @{LogName="Security"; Id=1102} -MaxEvents 5
```

## 11. Linux 应急排查命令

> 多数命令需要 root/sudo；先只读采集，避免修改系统。

```bash
# 账号
awk -F: '$3==0 {print $1}' /etc/passwd
grep -v '^#' /etc/sudoers
find / -name authorized_keys 2>/dev/null

# 进程
ps auxf
ls -l /proc/*/exe 2>/dev/null | grep deleted

# 网络
ss -tulnp
ss -antp state established
lsof -i -P -n

# 持久化
crontab -l
cat /etc/crontab
systemctl list-unit-files --state=enabled
ls -la /etc/cron.* /var/spool/cron*

# 文件
find /tmp /var/tmp /dev/shm -type f -executable 2>/dev/null
find / -perm -4000 -type f 2>/dev/null

# 日志
grep "Failed password" /var/log/auth.log
last -a
lastb
```

## 13. 常见错误

- 直接关机/重装，丢失证据
- 只处理单机，忽略横向
- 不重置凭据，攻击者回归
- 不修复入口，再次失陷
- 不保存日志，无法复盘
- 过早对外沟通，信息不一致
- 不评估数据泄露与合规
- 支付赎金
