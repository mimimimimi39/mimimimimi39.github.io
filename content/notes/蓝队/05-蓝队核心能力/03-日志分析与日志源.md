## 1. 日志为什么重要

安全运营的本质是「用数据还原事实」。日志是事实的主要来源：

- 谁在什么时间、从哪里、做了什么？
- 是否成功？
- 影响了什么资产/数据？
- 是否有后续行为？

**没有日志，就没有检测、研判、取证与复盘。**

## 2. 日志源地图

| 类别 | 数据源 | 能看到什么 |
|---|---|---|
| Windows | 安全日志、System、Application、Sysmon、PowerShell | 登录、账号、进程、服务、计划任务、脚本 |
| Linux | auth.log/secure、syslog/messages、auditd、journald | 登录、sudo、命令、服务、内核 |
| 网络 | 防火墙、路由器、交换机、VPN | 五元组、NAT、拦截、VPN 登录 |
| 安全设备 | WAF、IPS/IDS、EDR、邮件网关、沙箱 | 攻击特征、告警、样本判定 |
| 应用 | Web、API、业务系统 | 请求、业务操作、异常 |
| 数据库 | 错误日志、审计、binlog | SQL、登录、变更 |
| 身份 | AD/域控、IAM、SSO、MFA | 认证、权限变更、MFA |
| 云 | 云审计、流日志、对象存储日志 | API 调用、网络、访问 |
| 终端 | EDR、AV、HIDS | 进程、文件、网络、响应 |
| 备份/基础设施 | 备份系统、虚拟化、DNS、DHCP | 恢复、虚拟机操作、解析 |

## 3. 日志格式

### 3.1 Syslog

```text
<优先级>时间 主机 程序[PID]: 消息
```

- RFC 3164（旧）
- RFC 5424（新）

### 3.2 CEF

```text
CEF:0|Vendor|Product|Version|SignatureID|Name|Severity|Extension
```

常见于安全设备。

### 3.3 LEEF

IBM QRadar 常用格式。

### 3.4 JSON

现代应用与云日志常用，字段清晰，便于解析。

### 3.5 纯文本

自定义格式，需要正则/Grok 解析。

## 4. 时间与时区

- 统一使用 UTC 存储，展示时转换本地时区
- 确认设备时区与 NTP 同步
- 日志时间戳格式（ISO 8601 最佳）
- 时间漂移会导致时间线错误
- 跨时区事件要特别标注

**排查命令**：

```bash
date -u
timedatectl
w32tm /query /status
```

## 5. 归一化与字段

推荐统一字段：

| 字段 | 说明 |
|---|---|
| `timestamp` | 事件时间 |
| `host` / `hostname` | 主机 |
| `user` / `account` | 账号 |
| `src_ip` / `dst_ip` | 源/目的 IP |
| `src_port` / `dst_port` | 端口 |
| `process` / `command_line` | 进程/命令行 |
| `parent_process` | 父进程 |
| `file_path` / `file_hash` | 文件 |
| `event_type` / `action` / `result` | 事件类型/动作/结果 |
| `severity` | 严重级别 |
| `raw` | 原始日志 |

标准：ECS、OSSEM、Splunk CIM。

## 6. 采集与保留

### 6.1 采集方式

- Agent（Wazuh、Winlogbeat、Fluentd、Filebeat）
- Syslog 转发
- API 拉取
- 流量镜像
- 数据库读取
- 文件共享

### 6.2 保留

- 合规要求：网络安全法要求网络日志留存不少于六个月（具体以法规与行业要求为准）
- 热数据：最近 7-30 天，快速查询
- 温数据：3-6 个月
- 冷数据：1 年以上，归档
- 日志要可检索、可导出、可验证完整性

### 6.3 完整性

- 传输加密（TLS）
- 访问控制
- 防篡改（WORM、哈希链、独立日志服务器）
- 时间同步
- 备份
- 日志源健康监控

## 7. 关键日志详解

### 7.1 Windows 安全日志

| 事件 | 含义 | 调查价值 |
|---|---|---|
| 4624 | 登录成功 | 登录类型、来源、账号 |
| 4625 | 登录失败 | 爆破、密码喷洒 |
| 4648 | 显式凭据 | 横向、凭据滥用 |
| 4672 | 特殊权限 | 管理员活动 |
| 4688 | 进程创建 | 命令行、父进程 |
| 4698/4702 | 计划任务 | 持久化 |
| 4720/4732 | 账号/组变更 | 后门账号、提权 |
| 4768/4769 | Kerberos | 票据攻击 |
| 4697 | 服务安装（Security 日志） | 持久化 |
| 1102 | 安全日志清除 | 反取证 |

> 7045 是 System 日志中的服务安装事件；Security 日志对应 4697。排查时两者都值得看。详见 [Windows 日志分析](../06-主机与终端安全/02-Windows日志分析.md)。

### 7.2 Linux

| 日志 | 内容 |
|---|---|
| auth.log/secure | 登录、sudo、SSH |
| syslog/messages | 系统事件 |
| audit.log | 审计（execve、文件、权限） |
| journald | 统一日志 |
| cron | 计划任务 |
| Web access/error | HTTP 请求与错误 |

### 7.3 网络

- 防火墙：允许/拒绝、五元组、NAT
- VPN：登录、分配 IP、流量
- DNS：查询、响应
- 代理：URL、UA、上传下载
- NetFlow：会话统计
- IDS/NDR：告警与元数据

### 7.4 安全设备

- WAF：攻击类型、规则、动作、源 IP
- EDR：进程、文件、网络、响应动作
- 邮件网关：发件人、收件人、附件、URL、判定
- 沙箱：样本行为、IOC、家族

### 7.5 云

- 登录、MFA、IAM 变更
- 安全组/网络变更
- 对象存储访问
- 密钥使用
- 资源创建/删除
- 审计日志配置变更

## 8. 日志分析流程

```text
1. 明确问题/假设
2. 选择数据源
3. 确定时间范围与时区
4. 过滤关键字段
5. 聚合与关联
6. 查看原始日志
7. 形成结论与时间线
8. 保存证据
```

### 8.1 分析技巧

- 先宽后窄：先看整体，再定位
- 多源交叉：主机 + 网络 + 身份 + 应用
- 关注「第一次」与「最后一次」
- 关注异常时间、异常账号、异常来源
- 关注失败后的成功
- 关注正常行为的异常组合
- 不要只看告警，要看原始日志

## 9. 日志质量检查

| 检查项 | 问题 |
|---|---|
| 是否在采集 | 日志断流 |
| 时间是否准确 | 时区/NTP |
| 字段是否完整 | 解析失败 |
| 是否有重复 | 统计偏差 |
| 是否有敏感信息 | 合规风险 |
| 保留是否足够 | 无法回溯 |
| 是否可防篡改 | 证据无效 |
| 是否有告警 | 有数据无检测 |

## 10. 常见盲区

- 只看 Windows 不看 Linux
- 只看边界不看内网横向
- 只看告警不看原始日志
- 不采集 DNS/代理/身份日志
- 不采集云审计
- 日志时间不同步
- 日志被攻击者清除
- 日志留存不足
- 没有资产上下文

## 11. 实操

1. 在 Windows 事件查看器中导出 4624/4625/4688。
2. 在 Linux 分析 auth.log 的 SSH 登录。
3. 用 Wazuh/ELK 接入两类日志并查询。
4. 画出你所在环境（或实验环境）的日志源地图。
5. 检查日志时间是否同步。
6. 模拟日志断流并配置监控。
7. 为一个事件写时间线（至少 10 个时间点）。
