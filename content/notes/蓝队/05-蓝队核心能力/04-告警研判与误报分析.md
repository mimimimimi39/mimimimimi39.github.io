## 1. 什么是告警研判

告警研判（Triage）是对告警进行快速分类、验证、定性与定级，决定「是否真实、影响多大、怎么处理」。

目标：

- 快速排除误报
- 确认真实事件
- 判断影响范围与严重程度
- 决定升级/处置
- 留下可追溯的记录

---

## 2. 告警来源

- SIEM 关联规则
- EDR 行为检测
- AV/沙箱
- WAF/IPS
- 威胁情报匹配
- UEBA 异常
- 云安全告警
- 邮件网关
- 用户报告
- 漏洞扫描

---

## 3. 研判流程

```text
接收告警
  → 看告警基本信息（规则、时间、资产、账号、IOC）
  → 验证告警真实性（原始日志）
  → 补充上下文（资产、身份、情报、历史）
  → 判断误报/真实
  → 定性定级
  → 处置或升级
  → 记录工单
  → 复盘
```

## 4. 五要素与 5W1H

### 4.1 五要素

| 要素 | 问题 |
|---|---|
| 时间 | 什么时候发生？持续多久？ |
| 资产 | 哪台主机/哪个业务？重要性？ |
| 账号 | 哪个用户？权限？ |
| 行为 | 做了什么？成功了吗？ |
| 情报 | IP/域名/哈希是否恶意？ |

### 4.2 5W1H

- Who：谁
- What：做了什么
- When：何时
- Where：哪里
- Why：为什么（是否合理）
- How：怎么做的

## 5. 上下文来源

- 资产系统（CMDB）：负责人、业务、重要性、OS
- 身份系统（AD/IAM）：部门、角色、特权、近期变更
- 日志平台：前后时间段的关联事件
- EDR：进程树、网络、文件
- 威胁情报：IP/域名/哈希
- 漏洞系统：资产漏洞
- 变更系统：是否有计划变更
- 用户/业务确认

> 没有上下文的告警只是「一条日志」。研判的核心是**补上下文**。

## 6. 误报、真实与“真实但无害”

| 类型 | 定义 | 处理 |
|---|---|---|
| 误报（False Positive） | 规则错误/数据错误导致 | 调规则、加白名单 |
| 真实但无害（Benign True Positive） | 行为真实但符合业务 | 记录、加白名单/降低级别 |
| 真实恶意（True Positive） | 确认攻击/异常 | 升级、处置 |
| 未知 | 信息不足 | 继续调查或升级 |

> 很多「误报」其实是「真实但无害」。不要为了降误报而掩盖真实行为。

## 7. 定性定级

### 7.1 事件类型

- 恶意代码
- 入侵/Webshell
- 账号泄露
- 数据泄露
- 勒索
- 挖矿
- 钓鱼
- 拒绝服务
- 配置错误
- 合规事件

### 7.2 严重级别

| 级别 | 判断 |
|---|---|
| 紧急（Critical） | 核心资产失陷、数据泄露、勒索扩散 |
| 高（High） | 主机确认失陷、特权账号异常、横向 |
| 中（Medium） | 可疑行为、单点异常、需进一步调查 |
| 低（Low） | 低风险、尝试失败、信息性 |
| 信息（Info） | 仅记录 |

考虑因素：

- 资产重要性
- 数据敏感度
- 是否成功
- 影响范围
- 是否扩散
- 攻击者权限
- 业务影响
- 合规要求

## 8. 典型告警研判示例

### 8.1 SSH 暴力破解

**告警**：同一 IP 10 分钟内失败 100 次。

**调查**：

1. 查看 auth.log 原始日志：源 IP、目标账号、时间。
2. 是否有成功登录（Accepted）？
3. 成功登录后执行了什么命令？
4. 源 IP 是否情报恶意/扫描器？
5. 是否其他主机也被尝试？
6. 账号是否弱口令？

**结论**：

- 仅失败 → 低/中，封禁 IP，加强防护。
- 失败后成功 → 高，立即排查主机、改密、隔离。

### 8.2 恶意 IP 外联

**告警**：主机访问已知恶意 IP。

**调查**：

1. 哪个进程发起连接？（Sysmon 3/EDR）
2. 进程路径、签名、父进程、命令行。
3. 连接频率、端口、协议、流量大小。
4. 是否有文件落地、注册表/服务变更。
5. 其他主机是否也外联？
6. 情报是否确认恶意？是否误报（CDN/共享 IP）？

**结论**：

- 浏览器访问恶意站点 → 中，终端排查。
- 未知进程固定心跳 → 高，C2 疑似，隔离。

### 8.3 Webshell 访问

**告警**：Web 目录新增 `.php` 文件并被 POST 访问。

**调查**：

1. 文件内容、创建时间、权限、哈希。
2. 上传入口（Web 日志）。
3. 访问日志中的参数、UA、响应大小。
4. Web 进程是否拉起 shell。
5. 是否有横向、持久化、数据外传。
6. 同目录其他文件是否被修改。

**结论**：确认为 Webshell → 高/紧急，隔离、清除、修复入口。

### 8.4 异常 PowerShell

**告警**：`powershell -enc ...`。

**调查**：

1. 解码 Base64（安全环境）。
2. 父进程（Office？浏览器？服务？）。
3. 用户与时间。
4. 网络连接与下载。
5. 文件落地。
6. 是否管理员操作/自动化脚本。

**结论**：宏/钓鱼拉起 → 高；管理员脚本 → 记录并加白。

## 9. 升级与处置

### 9.1 立即升级

- 核心资产确认失陷
- 数据泄露
- 勒索扩散
- 特权账号异常
- 横向移动
- 高管/合规相关

### 9.2 常见处置

| 场景 | 处置 |
|---|---|
| 恶意 IP | 封禁、监控 |
| 恶意域名 | DNS 拦截、代理封禁 |
| 恶意文件 | 隔离、删除、哈希封禁 |
| 失陷主机 | 网络隔离、取证、重装 |
| 账号泄露 | 禁用、改密、撤销会话、MFA |
| 钓鱼邮件 | 删除邮件、封禁发件人、通知用户 |
| Webshell | 隔离、清除、修复入口 |
| 勒索 | 隔离、断网、备份、上报 |

> 处置前尽量保存证据；处置动作要记录。

## 11. 沟通与写作

- 结论先行：是否为事件、级别、影响。
- 事实与推测分开。
- 时间线清晰。
- 避免术语堆砌，让非技术人员看懂。
- 不隐瞒不确定性。
- 敏感信息按规范处理。

---

## 12. 常见错误

| 错误 | 后果 |
|---|---|
| 只看告警标题 | 误判 |
| 不看原始日志 | 被规则误导 |
| 不查资产重要性 | 级别错误 |
| 不查情报 | 漏判/误判 |
| 不关联前后事件 | 漏掉攻击链 |
| 过度依赖白名单 | 漏报 |
| 处置不留证据 | 无法复盘/追责 |
| 不记录结论 | 重复劳动 |

---

## 13. 实操

1. 选 5 条真实/模拟告警，按五要素分析。
2. 为每条告警补充资产、账号、情报上下文。
3. 判断误报/真实但无害/真实恶意。
4. 写完整工单。
5. 与同学互相评审工单。
6. 复盘一次误报，提出规则优化建议。
7. 模拟一次升级沟通。
