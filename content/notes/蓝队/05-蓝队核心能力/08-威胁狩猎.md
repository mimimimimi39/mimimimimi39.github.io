## 1. 什么是威胁狩猎

威胁狩猎（Threat Hunting）是**主动**假设攻击者可能已经潜伏，用数据与分析方法验证假设，发现传统告警未能覆盖的威胁。

与 SOC 监控的区别：

| 维度 | SOC 监控 | 威胁狩猎 |
|---|---|---|
| 触发 | 告警 | 假设/情报/异常 |
| 方式 | 被动 | 主动 |
| 目标 | 响应已知 | 发现未知/漏报 |
| 产出 | 工单 | 新检测规则、发现、改进 |
| 时间 | 持续 | 项目制/周期 |

> 狩猎不是「随便翻日志」，而是有假设、有数据、有方法、有产出的过程。

---

## 2. 狩猎类型

| 类型 | 起点 | 例子 |
|---|---|---|
| 假设驱动 | 攻击者可能怎么做 | 「攻击者可能用 PsExec 横向」 |
| 情报驱动 | 新 IOC/TTP/报告 | 「某 APT 使用新的 C2 框架」 |
| 数据驱动 | 异常统计 | 「某主机外连量突增」 |
| 分析驱动 | 已有事件扩展 | 「同网段是否还有其他失陷」 |
| ATT&CK 驱动 | 覆盖缺口 | 「我们是否能检测 T1053」 |

---

## 3. 狩猎循环

```text
1. 形成假设
2. 选择数据源与时间范围
3. 查询与分析
4. 验证结果（排除误报）
5. 若发现威胁 → 转应急
6. 若无发现 → 记录假设与覆盖
7. 产出检测规则/改进项
8. 复盘
```

---

## 4. 方法论

### 4.1 TaHiTI

- 发起（Initiate）：由威胁情报、监控缺口、事件响应等触发
- 狩猎（Hunt）：提出假设、选择数据、执行查询并验证
- 收尾（Finalize）：记录结论、沉淀检测规则、复盘改进

### 4.2 PEAK（Prepare, Execute, Act with Knowledge）

- Prepare：确定目标、范围、数据
- Execute：执行狩猎
- Act：响应、改进、分享

### 4.3 基于 ATT&CK

- 选择战术/技术
- 确定数据源
- 设计检测假设
- 验证覆盖
- 补充规则

## 5. 假设示例

| 假设 | 数据源 | 查询思路 |
|---|---|---|
| 攻击者使用异常父进程执行 PowerShell | Sysmon 1、4688 | Office/浏览器 → PowerShell |
| 攻击者访问 LSASS 窃取凭据 | Sysmon 10、EDR | 非安全软件进程访问 LSASS |
| 攻击者创建计划任务持久化 | 4698、Sysmon 1 | 非常规任务、可疑命令 |
| 攻击者使用 DNS 隧道 | DNS、Zeek | 长域名、高熵、TXT |
| 攻击者横向使用 PsExec | 7045、4624、流量 | 服务创建 + 445 + 登录 |
| 攻击者使用云 API 创建后门 | 云审计 | CreateUser/CreateAccessKey |
| 攻击者使用合法工具下载 | 代理、Sysmon 3 | certutil/bitsadmin/curl |
| 攻击者清除日志 | 1102、104 | 日志清除事件 |

## 6. 实战案例：异常 PowerShell

### 假设

攻击者可能通过 Office 宏或钓鱼附件执行 PowerShell。

### 查询（Splunk）

```spl
index=windows EventCode=4688
| search ParentProcessName="*\\winword.exe" OR ParentProcessName="*\\excel.exe" OR ParentProcessName="*\\outlook.exe"
| search NewProcessName="*powershell.exe" OR NewProcessName="*cmd.exe" OR NewProcessName="*mshta.exe"
| table _time host user ParentProcessName NewProcessName CommandLine
```

> 4688 的 `ParentProcessName` 是完整路径，精确匹配 `winword.exe` 通常不命中；需用通配符，或在 SIEM 中使用规范化后的进程名字段。

### 验证

- 是否业务需要（宏、插件）？
- 命令行是否含下载/编码？
- 是否有网络连接？
- 是否文件落地？
- 是否多台主机？

### 产出

- 若确有异常 → 升级事件
- 若无异常 → 加白名单/调整规则
- 新增检测规则：Office → PowerShell

## 7. 实战案例：C2 心跳

### 假设

恶意软件可能以固定间隔外连 C2。

### 数据源

- 代理日志
- 防火墙/NetFlow
- Zeek conn.log
- DNS

### 分析

- 同一目标、固定间隔（如每 60 秒 ± 抖动）
- 小包、低流量
- 长时间持续
- 非业务域名/新域名
- JA3/JA3S 异常

### 查询思路

```text
按 src_ip + dst_ip 分组
计算连接时间间隔的方差
方差很小且持续多天 → 可疑心跳
```

### 产出

- 可疑域名/IP 情报查询
- 终端进程定位
- 新增检测规则

## 8. 实战案例：横向移动

### 假设

攻击者可能使用 PsExec/WMI/WinRM 横向。

### 数据源

- 7045 服务安装
- 4624 类型 3/10
- 4672
- Sysmon 1/3
- 流量 445/135/5985

### 查询

```spl
index=windows EventCode=7045
| table _time host ServiceName ImagePath AccountName
| search ImagePath="*\\Windows\\*" OR ImagePath="*Temp*" OR ImagePath="*ADMIN$*"
```

### 验证

- 服务名是否随机（如 `PSEXESVC`、随机字符串）
- 服务路径是否异常
- 是否伴随登录与文件传输
- 是否多台主机

## 9. 数据源与工具

| 数据源 | 用途 |
|---|---|
| Sysmon | 进程、网络、文件、注册表 |
| Windows 安全日志 | 登录、账号、服务、任务 |
| EDR | 行为、内存、响应 |
| Zeek | 网络元数据 |
| Suricata | 流量告警 |
| DNS/代理 | 域名与 URL |
| 云审计 | API 行为 |
| 身份日志 | 登录、MFA、权限 |

工具：

- SIEM 查询
- Velociraptor（终端狩猎）
- osquery
- Zeek/Arkime
- ATT&CK Navigator
- Sigma
- Jupyter/pandas（数据分析）
- RITA（C2 分析，维护状态需确认）

## 10. 狩猎产出

- 发现的事件（转 IR）
- 新的检测规则
- 数据源缺口
- 日志/字段改进
- ATT&CK 覆盖更新
- 狩猎报告
- 复盘与知识库

> 没有产出的狩猎只是「看日志」。即使没发现威胁，也要产出「假设已验证/数据缺口」。

## 11. 成熟度

| 级别 | 特征 |
|---|---|
| 0 | 无狩猎 |
| 1 | 临时、无方法 |
| 2 | 有假设、有数据 |
| 3 | 有流程、有产出 |
| 4 | 情报/ATT&CK 驱动、自动化 |
| 5 | 持续运营、度量、行业共享 |

---

## 12. 常见误区

- 没有假设，随便查
- 只看单一数据源
- 不建立基线
- 把误报当发现
- 不产出规则
- 不记录过程
- 狩猎范围过大，无法收敛
- 忽略内部情报与业务上下文

---

## 13. 实操

1. 选一个 ATT&CK 技术，写狩猎假设。
2. 确定数据源与时间范围。
3. 写查询并分析结果。
4. 验证误报。
5. 产出检测规则或数据缺口。
6. 写狩猎报告。
7. 用 ATT&CK Navigator 更新覆盖。
