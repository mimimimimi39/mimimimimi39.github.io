## 1. 为什么蓝队要学数据库

- 企业核心数据在数据库中，数据库是攻击者的重点目标。
- SQL 注入是最常见的 Web 漏洞之一。
- 数据库日志、审计日志是发现数据泄露与内部违规的重要数据源。
- 应急响应需要判断数据是否被拖库、篡改、删除。

---

## 2. 数据库分类

| 类型 | 代表 | 特点 | 场景 |
|---|---|---|---|
| 关系型（RDBMS） | MySQL、PostgreSQL、SQL Server、Oracle | 表、行、列、SQL、事务 | 业务系统 |
| 键值 | Redis、Memcached | 高性能缓存 | 缓存、会话 |
| 文档 | MongoDB | JSON 文档 | 灵活结构 |
| 列式 | Cassandra、HBase | 大规模写入 | 大数据 |
| 搜索 | Elasticsearch | 全文检索 | 日志、搜索 |
| 图 | Neo4j | 关系图 | 关系分析 |
| 时序 | InfluxDB、Prometheus | 时间序列 | 监控 |

蓝队常见：MySQL、SQL Server、Oracle、PostgreSQL、Redis、MongoDB、Elasticsearch。

## 3. 关系型数据库核心概念

| 概念 | 说明 |
|---|---|
| 表（Table） | 数据的二维结构 |
| 行（Row） | 一条记录 |
| 列（Column） | 字段 |
| 主键（Primary Key） | 唯一标识一行 |
| 外键（Foreign Key） | 关联另一张表 |
| 索引（Index） | 加速查询 |
| 视图（View） | 虚拟表 |
| 事务（Transaction） | 一组原子操作 |
| 存储过程（Procedure） | 数据库内程序 |
| 触发器（Trigger） | 自动执行的逻辑 |

## 4. SQL 基础

### 4.1 查询

```sql
SELECT id, username, last_login
FROM users
WHERE status = 'active'
ORDER BY last_login DESC
LIMIT 10;
```

### 4.2 聚合

```sql
SELECT src_ip, COUNT(*) AS failures
FROM login_logs
WHERE event_type = 'failed'
GROUP BY src_ip
HAVING COUNT(*) > 20
ORDER BY failures DESC;
```

### 4.3 关联

```sql
SELECT u.username, l.src_ip, l.login_time
FROM users u
JOIN login_logs l ON u.id = l.user_id
WHERE l.login_time > '2026-11-01';
```

### 4.4 子查询

```sql
SELECT username
FROM users
WHERE id IN (
  SELECT user_id FROM login_logs WHERE src_ip = '203.0.113.10'
);
```

### 4.5 修改

```sql
INSERT INTO users (username, status) VALUES ('test', 'active');
UPDATE users SET status = 'disabled' WHERE username = 'test';
DELETE FROM users WHERE username = 'test';
```

> 生产环境执行 UPDATE/DELETE 前必须备份并确认 WHERE 条件。

## 5. 索引、事务与锁

### 5.1 索引

- 加速 SELECT
- 增加写入成本与存储
- 常见：B+ 树、哈希、全文索引

### 5.2 事务 ACID

| 特性 | 含义 |
|---|---|
| 原子性（Atomicity） | 要么全成功，要么全失败 |
| 一致性（Consistency） | 事务前后数据一致 |
| 隔离性（Isolation） | 并发事务互不干扰 |
| 持久性（Durability） | 提交后持久保存 |

### 5.3 隔离级别

| 级别 | 脏读 | 不可重复读 | 幻读 |
|---|---|---|---|
| Read Uncommitted | 可能 | 可能 | 可能 |
| Read Committed | 否 | 可能 | 可能 |
| Repeatable Read | 否 | 否 | 可能 |
| Serializable | 否 | 否 | 否 |

> MySQL InnoDB 默认 Repeatable Read，并通过间隙锁减少幻读。

### 5.4 锁

- 共享锁、排他锁
- 行锁、表锁
- 死锁

蓝队注意：大量锁等待可能是攻击（如拖库、批量操作）或业务异常。

## 6. 数据库日志

### 6.1 MySQL

| 日志 | 作用 | 位置/配置 |
|---|---|---|
| 错误日志 | 启动、错误、崩溃 | `log_error` |
| 通用查询日志 | 所有 SQL | `general_log`，默认关闭 |
| 慢查询日志 | 慢 SQL | `slow_query_log` |
| 二进制日志（binlog） | 数据变更、复制、恢复 | `log_bin` |
| 审计日志 | 审计（企业版/插件） | 插件配置 |
| 中继日志 | 从库复制 | `relay_log` |

### 6.2 SQL Server

| 日志 | 作用 |
|---|---|
| 错误日志 | 启动、错误 |
| 事务日志（LDF） | 事务恢复 |
| SQL Server Audit | 审计 |
| 默认跟踪（Default Trace） | 配置变更 |
| 扩展事件（Extended Events） | 诊断 |

### 6.3 PostgreSQL

| 日志 | 作用 |
|---|---|
| `log_directory`（默认 `log`；旧版为 `pg_log`） | 错误、慢查询 |
| WAL | 预写日志、恢复 |
| `pg_stat_activity` | 当前会话 |
| `pgaudit` | 审计扩展 |

### 6.4 蓝队关注

- 异常登录（来源 IP、时间、账号）
- 大批量 SELECT/导出
- 异常 UPDATE/DELETE
- 新账号、权限变更
- 存储过程/触发器变更
- 数据库配置修改
- 备份异常

## 7. 数据库安全配置

### 7.1 账号与权限

- 禁止 root/SA 远程登录
- 最小权限原则
- 应用账号只授予必要权限
- 禁止应用账号拥有 FILE、SUPER、xp_cmdshell 等
- 定期清理过期账号
- 强密码与多因素

### 7.2 网络与访问

- 数据库不暴露公网
- 仅允许应用服务器访问
- 使用防火墙/安全组
- 使用 TLS 加密连接

### 7.3 数据安全

- 敏感字段加密/脱敏
- 备份加密
- 审计日志保护
- 数据分类分级

### 7.4 配置加固

- 删除测试库/示例库
- 关闭不必要的功能（如 xp_cmdshell）
- 开启审计
- 及时打补丁
- 修改默认端口（降低噪音）
- 限制文件导入导出

## 8. 常见数据库攻击

| 攻击 | 说明 | 检测线索 |
|---|---|---|
| 弱口令/爆破 | 尝试常见密码 | 登录失败日志、来源 IP |
| SQL 注入 | 通过 Web 参数执行 SQL | Web 日志、WAF、数据库错误日志 |
| 未授权访问 | Redis/MongoDB/ES 暴露 | 端口扫描、异常连接 |
| 权限提升 | 利用数据库漏洞/配置 | 账号权限变更、异常命令 |
| 拖库 | 大批量查询/导出 | 大查询、慢查询、外传流量 |
| 篡改/删除 | 恶意 UPDATE/DELETE | binlog、审计日志 |
| 命令执行 | xp_cmdshell、UDF、存储过程 | 数据库进程异常、系统命令 |
| 备份窃取 | 下载备份文件 | 文件访问、网络外传 |
| 供应链/插件 | 恶意插件、扩展 | 插件目录变更 |

### 8.1 Redis 未授权

- 旧版本默认无密码且可能绑定 0.0.0.0；Redis 3.2+ 默认只监听 127.0.0.1 并开启 protected-mode，暴露通常是配置被改过
- 可写 SSH 公钥、计划任务、Webshell
- 检测：6379 暴露、`CONFIG SET`、`SAVE`、异常写入

### 8.2 MongoDB 未授权

- 默认无认证
- 检测：27017 暴露、异常查询/导出

### 8.3 Elasticsearch 未授权

- 7.x 及更早默认无认证；8.x 默认启用安全认证，暴露通常是配置被改过
- 检测：9200 暴露、索引删除、数据导出

## 9. 数据库应急排查

1. 确认数据库类型、版本、端口。
2. 检查账号与权限（是否有陌生账号、超级权限）。
3. 检查登录日志与审计日志（来源 IP、时间、失败次数）。
4. 检查异常 SQL（大批量查询、导出、修改）。
5. 检查数据库配置（远程访问、文件权限、xp_cmdshell）。
6. 检查数据库文件与备份是否被篡改/加密。
7. 检查主机层面（进程、网络、文件、计划任务）。
8. 保存证据，评估数据泄露范围。
9. 重置凭据、修复入口、加强监控。

1. 安装 MySQL，创建库、表、用户，练习 CRUD。
2. 用 SQL 统计登录失败次数最多的 IP。
3. 开启慢查询日志，观察记录。

6. 用 Wireshark 抓取 MySQL 登录过程（如未加密）。
7. 阅读一条 SQL 注入的 Web 日志与数据库错误日志。
