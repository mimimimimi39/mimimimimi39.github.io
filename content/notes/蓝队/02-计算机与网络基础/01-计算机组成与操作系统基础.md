## 1. 为什么蓝队要学这个

蓝队排查问题时，看到的是：

- 一个进程树
- 一段内存
- 一个文件的时间戳
- 一条注册表修改
- 一个系统调用

如果不理解操作系统如何管理 CPU、内存、进程、文件，就无法判断「这个行为正常还是异常」。

---

## 2. 计算机的基本组成

### 2.1 五大部件

| 部件 | 作用 | 蓝队关注点 |
|---|---|---|
| 运算器（ALU） | 算术与逻辑运算 | 加密、哈希、编译 |
| 控制器（CU） | 取指、译码、执行 | 指令执行、CPU 架构 |
| 存储器 | 寄存器、缓存、内存、磁盘 | 内存取证、文件时间戳 |
| 输入设备 | 键盘、鼠标、网络 | 钓鱼、恶意输入 |
| 输出设备 | 显示器、打印机、网络 | 数据外传 |

现代 CPU 通常把运算器与控制器集成在一起，称为 CPU。

### 2.2 存储层次

```text
寄存器       最快、最小、最贵
  ↓
L1/L2/L3 缓存
  ↓
内存（RAM）   断电丢失
  ↓
SSD/HDD      持久化
  ↓
网络/磁带     更慢、更大
```

**蓝队意义**：

- 内存中有进程、网络连接、凭据、密钥、恶意代码片段 → 内存取证。
- 磁盘中有文件、日志、注册表、数据库 → 磁盘取证。
- 断电后内存数据丢失 → 应急时要优先保存内存。

### 2.3 数据表示

- 二进制：0/1
- 字节：8 bit
- 十六进制：`0x41` = 65 = 字符 `A`
- 字符编码：ASCII、UTF-8、UTF-16、GBK

蓝队常见场景：

- 日志中的十六进制、Base64、URL 编码
- 恶意样本中的字符串
- 流量中的二进制协议
- 哈希值

推荐工具：CyberChef（https://gchq.github.io/CyberChef/）。

## 3. 操作系统做什么

操作系统是硬件与应用之间的管理者，核心职责：

1. **进程管理**：创建、调度、销毁进程。
2. **内存管理**：虚拟内存、分页、隔离。
3. **文件系统**：文件的组织、权限、元数据。
4. **设备管理**：驱动、I/O。
5. **网络管理**：协议栈、套接字。
6. **用户与权限**：认证、授权、审计。

### 3.1 用户态与内核态

| 状态 | 权限 | 例子 |
|---|---|---|
| 用户态（Ring 3） | 受限 | 普通应用、浏览器 |
| 内核态（Ring 0） | 最高 | 内核、驱动 |

应用访问硬件或执行特权操作，需要通过**系统调用**进入内核态，例如：

- 读写文件：`open/read/write`
- 创建进程：`fork/exec`（Linux）、`CreateProcess`（Windows）
- 网络连接：`socket/connect`
- 内存分配：`mmap`、`VirtualAlloc`

**蓝队意义**：恶意软件常用系统调用直接操作内存、进程、网络。EDR 会监控这些调用与内核回调。

### 3.2 进程与线程

| 概念 | 说明 |
|---|---|
| 程序 | 磁盘上的可执行文件 |
| 进程 | 运行中的程序实例，拥有独立地址空间 |
| 线程 | 进程内的执行单元，共享地址空间 |
| PID | 进程 ID |
| PPID | 父进程 ID |
| 句柄/文件描述符 | 进程打开的文件、套接字、注册表等资源 |

**进程树**是蓝队排查的核心线索：

```text
explorer.exe
  └─ chrome.exe
       └─ cmd.exe
            └─ powershell.exe -enc ...
```

异常父子关系示例：

- `winword.exe` → `powershell.exe`（宏执行）
- `w3wp.exe` → `cmd.exe`（Webshell）
- `services.exe` → 异常子进程（服务被滥用）
- `sshd` → `bash` → `curl`（Linux 入侵）

### 3.3 虚拟内存

每个进程看到的是独立的虚拟地址空间，由操作系统映射到物理内存。

- 分页（Paging）：内存按页管理。
- 交换（Swap/Pagefile）：内存不足时写到磁盘。
- 内存映射文件（mmap）：文件映射到内存。

**蓝队意义**：

- 内存马、无文件攻击常驻内存，磁盘无文件。
- 内存取证可提取进程、网络连接、注入代码。
- Pagefile/Swap 可能残留敏感数据。

### 3.4 文件系统

| 系统 | 常见文件系统 | 特点 |
|---|---|---|
| Windows | NTFS、ReFS、FAT32 | 权限 ACL、ADS、日志 |
| Linux | ext4、XFS、Btrfs | inode、权限位 |
| macOS | APFS | 快照、加密 |

**关键元数据**：

- 创建时间、修改时间、访问时间、MFT 修改时间（Windows）
- inode、权限、属主、大小（Linux）
- 文件哈希
- 扩展属性、ADS（NTFS 备用数据流）

**蓝队意义**：

- 时间戳可被篡改（Timestomping）。
- NTFS ADS 可隐藏数据。
- Linux `mtime/ctime/atime` 可帮助构建时间线。

### 3.5 启动流程

#### Windows

```text
UEFI/BIOS → Windows Boot Manager → winload.efi（UEFI）/ winload.exe（BIOS）→ 内核 ntoskrnl.exe
→ 会话管理器 smss.exe
   ├─ csrss.exe
   ├─ wininit.exe → services.exe / lsass.exe
   └─ winlogon.exe → userinit.exe → explorer.exe → 用户应用
```

安全关注：

- 引导扇区/Bootkit
- 驱动签名
- 服务与启动项
- 登录认证（LSASS）
- 计划任务

#### Linux

```text
BIOS/UEFI → GRUB → 内核 vmlinuz → initramfs → systemd（PID 1）
→ 各服务 → 登录管理器/SSH
```

安全关注：

- GRUB 密码与内核参数
- initramfs 是否被篡改
- systemd 服务与定时器
- 内核模块（rootkit）
- `/etc/rc.local`、profile、cron

## 4. 系统调用与 API

### 4.1 Linux 常见系统调用

| 调用 | 作用 |
|---|---|
| `fork` / `clone` | 创建进程/线程 |
| `execve` | 执行程序 |
| `openat` | 打开文件 |
| `read` / `write` | 读写 |
| `socket` / `connect` | 网络 |
| `ptrace` | 进程调试/注入 |
| `mmap` / `mprotect` | 内存映射/权限修改 |
| `setuid` | 设置用户 ID |

### 4.2 Windows 常见 API

| API | 作用 | 攻击用途 |
|---|---|---|
| `CreateProcess` | 创建进程 | 执行恶意程序 |
| `OpenProcess` | 打开进程 | 注入、读取内存 |
| `VirtualAllocEx` | 远程分配内存 | 进程注入 |
| `WriteProcessMemory` | 写远程内存 | 注入 Shellcode |
| `CreateRemoteThread` | 远程创建线程 | 执行注入代码 |
| `SetWindowsHookEx` | 全局钩子 | 键盘记录 |
| `RegSetValueEx` | 修改注册表 | 持久化 |
| `CreateService` | 创建服务 | 持久化/提权 |

> 蓝队不需要会写这些 API，但看到 Sysmon/EDR 告警中的 API 名称要能判断风险。

## 5. 蓝队视角：从系统机制到检测

| 系统机制 | 攻击滥用 | 检测数据源 |
|---|---|---|
| 进程创建 | 执行恶意程序 | Sysmon 1、4688、EDR |
| 父进程关系 | 异常父子链 | Sysmon 1、EDR |
| 内存 | 注入、无文件 | Sysmon 8/10、EDR、内存取证 |
| 文件 | 落地木马、篡改 | Sysmon 11、文件完整性监控 |
| 注册表 | 持久化、配置篡改 | Sysmon 12/13/14 |
| 服务 | 持久化、提权 | 7045、4697、Sysmon 1 |
| 计划任务 | 持久化 | 4698/4699/4702、Sysmon 1 |
| 网络 | C2、横向、外传 | Sysmon 3、防火墙、Zeek、NetFlow |
| 登录 | 爆破、横向 | 4624/4625/4648、Linux auth.log |
| 启动项 | 持久化 | Autoruns、Sysmon 13、注册表 |

## 6. 动手练习

1. 在 Windows 任务管理器中找到 `explorer.exe` 的 PID、父进程、命令行（可用 Process Explorer）。
2. 在 Linux 用 `ps -ef --forest` 查看进程树，找出 PID 1。
3. 用 `stat` 查看一个文件的 atime/mtime/ctime。
4. 用 PowerShell 查看一个进程的加载模块。
5. 用 Wireshark 观察一次 DNS 查询与 TCP 连接。
6. 画一张「浏览器访问网页」的进程、网络、文件交互图。

## 7. 常见误区

- 把「进程」和「程序」混为一谈。
- 认为删除文件就一定无法恢复。
- 认为内存数据关机后一定消失（休眠文件、Pagefile 可能残留）。
- 只看进程名，不看命令行、父进程、签名、哈希。
- 认为 Linux 不会中病毒。
