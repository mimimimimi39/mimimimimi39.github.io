## 1. 为什么需要项目

简历上的「熟悉 Wireshark」「了解应急响应」没有说服力。项目能证明：

- 你真的动手做过
- 你能把知识串起来
- 你能写清楚过程和结论
- 你能解决具体问题

> 目标：做出 1-2 个能讲 5-10 分钟、经得起追问的项目。

---

## 2. 项目一：迷你 SOC（推荐）

### 2.1 目标

搭建一个能采集日志、产生告警、支持研判的迷你 SOC。

### 2.2 架构

```text
Windows 受害机（Sysmon + 审核策略）
Linux 受害机（auditd + rsyslog）
  → Wazuh Manager / ELK
  → 告警 → 仪表盘 → 工单
Kali 攻击机（模拟攻击）
```

### 2.3 步骤

1. 搭建虚拟机与隔离网络。
2. 部署 Wazuh/ELK。
3. 接入 Windows/Linux 日志。
4. 配置 Sysmon 与审核策略。
5. 用 Atomic Red Team 或手工模拟 5 个 ATT&CK 技术。
6. 编写/启用检测规则。
7. 产生告警并研判。
8. 写事件报告与复盘。
9. 优化规则，记录前后对比。

### 2.4 产出

- 架构图
- 部署文档
- 检测规则（Sigma/Wazuh）
- 告警研判报告
- 事件报告
- ATT&CK 覆盖表
- GitHub 仓库

### 2.5 简历描述示例

```text
搭建基于 Wazuh + Sysmon 的迷你 SOC 实验环境，接入 Windows/Linux 日志，
模拟 5 类 ATT&CK 攻击并编写检测规则，完成告警研判与应急报告，
将某类告警误报率从 X% 降至 Y%。
```

## 3. 项目二：日志分析平台

### 3.1 目标

用 ELK/Splunk 搭建日志分析平台，完成 Web 攻击检测。

### 3.2 步骤

1. 部署 Elasticsearch/Logstash/Kibana 或 Splunk Free。
2. 接入 Nginx/Apache、Windows、Linux 日志。
3. 解析字段（Grok/正则/JSON）。
4. 建立仪表盘（Top IP、状态码、攻击类型）。
5. 模拟 SQLi/XSS/扫描/爆破。
6. 编写检测查询。
7. 写分析报告。

### 3.3 产出

- 日志接入文档
- 解析规则
- 仪表盘截图
- 检测查询
- 攻击分析报告

---

## 4. 项目三：恶意样本分析报告集

### 4.1 目标

分析 3-5 个公开恶意样本（教育用途），产出报告。

### 4.2 步骤

1. 隔离环境（REMnux + Flare VM）。
2. 计算哈希，查询情报。
3. 静态分析（PE、字符串、导入表）。
4. 动态分析（Procmon、Wireshark、沙箱）。
5. 提取 IOC。
6. 写 YARA 规则。
7. 写报告。

### 4.3 产出

- 样本报告
- IOC 表
- YARA 规则
- 检测建议

> 不传播样本，遵守平台条款与法律。

---

## 5. 项目四：流量分析案例集

### 5.1 目标

分析 5-10 个公开 PCAP（如 Malware Traffic Analysis），产出报告。

### 5.2 步骤

1. 下载 PCAP 与题目。
2. 看协议分布与会话。
3. 定位恶意流量。
4. 跟踪流/导出对象。
5. 提取 IOC。
6. 写检测规则。
7. 写报告。

### 5.3 产出

- 每个 PCAP 的分析报告
- IOC
- Suricata/Zeek 规则
- 时间线

---

## 6. 项目五：应急响应演练

### 6.1 目标

在实验环境模拟一次完整入侵，完成应急响应。

### 6.2 场景

- Web 上传 Webshell
- 弱口令 RDP 爆破
- 钓鱼附件执行
- 挖矿/勒索（无害模拟）

### 6.3 步骤

1. 设计攻击链。
2. 执行攻击（仅实验环境）。
3. 从告警/日志发现。
4. 隔离、取证、排查。
5. 清除、恢复。
6. 写应急报告。
7. 复盘与规则更新。

### 6.4 产出

- 攻击链
- 时间线
- 证据
- 应急报告
- 改进项

---

## 7. 项目六：检测工程

### 7.1 目标

用 Sigma + Atomic Red Team 做检测覆盖。

### 7.2 步骤

1. 选 10 个 ATT&CK 技术。
2. 找/写 Sigma 规则。
3. 转换为 SIEM 查询。
4. 用 Atomic Red Team 模拟。
5. 验证命中/误报。
6. 更新覆盖图。
7. 写报告。

### 7.3 产出

- Sigma 规则
- 测试记录
- ATT&CK Navigator 覆盖图
- 改进建议

---

## 8. 项目七：自动化 IR 工具

### 8.1 目标

写一个跨平台应急信息采集脚本。

### 8.2 功能

- 进程、网络、账号、服务、任务、启动项
- 日志导出
- 哈希计算
- 输出压缩包
- 日志记录
- 安全（只读、不修改系统）

### 8.3 产出

- 脚本（Python/PowerShell/Bash）
- 使用文档
- 测试记录

> 注意：不要采集敏感数据，不要影响业务。

## 9. 项目八：云/容器安全实验

### 9.1 目标

搭建 K8s 实验环境，做容器安全检测。

### 9.2 步骤

7. 写加固建议。

### 9.3 产出

- 集群架构
- 扫描报告
- 检测规则
- 加固清单

## 14. 常见问题

### Q1：没有真实企业环境怎么办？

用虚拟机 + 公开样本 + 靶场模拟。重点是分析过程与报告，不是环境规模。

### Q2：项目会不会太简单？

简单项目做深也有价值：完整日志、规则、误报、复盘、改进。比堆名词强。

### Q3：可以写靶场 Writeup 吗？

可以，但要加入自己的分析、检测规则与复盘，不要只抄答案。

### Q4：需要多少项目？

1 个主项目 + 2-3 个小案例即可。质量 > 数量。
