## 1. 安全第一

样本分析必须在隔离环境进行：

- 独立虚拟机，快照
- 不共享文件夹/剪贴板/拖拽
- 内部网络或断网
- 不登录个人账号
- 不连接生产网络
- 样本加密压缩保存
- 遵守法律与企业规定

> 任何样本都可能在你不注意时逃逸或外联。不要抱有侥幸心理。

---

## 2. 分析流程

```text
接收样本 → 哈希/备份 → 静态分析 → 动态分析 → 行为归纳
→ IOC 提取 → 家族判断 → 检测规则 → 报告
```

## 3. 静态分析

### 3.1 基础信息

```bash
sha256sum sample.exe
md5sum sample.exe
file sample.exe
strings -a sample.exe | head -100
strings -el sample.exe | head -100   # UTF-16
```

Windows：

```powershell
Get-FileHash sample.exe -Algorithm SHA256
Get-Item sample.exe | Format-List *
```

记录：

- 文件名、大小、类型
- 哈希（MD5/SHA1/SHA256）
- 编译时间
- 签名
- 图标/资源
- 字符串

### 3.2 PE 结构

| 部分 | 内容 |
|---|---|
| DOS Header | `MZ` |
| NT Header | `PE\0\0` |
| File Header | 架构、节数量、时间戳 |
| Optional Header | 入口点、镜像基址、子系统 |
| Section Headers | `.text`、`.data`、`.rdata`、`.rsrc` |
| Import Table | 导入函数 |
| Export Table | 导出函数 |
| Resources | 图标、版本、嵌入文件 |
| Digital Signature | 签名 |
| Overlay | 附加数据 |

工具：

- PE-bear
- CFF Explorer
- Detect It Easy（DIE）
- pestudio
- PEview（旧）

关注：

- 入口点异常
- 节名异常（UPX、.packed）
- 节熵高（加壳/加密）
- 导入函数少（动态解析）
- 可疑 API（`VirtualAlloc`、`CreateRemoteThread`、`WriteProcessMemory`、`InternetOpen`、`CryptEncrypt`）
- 无签名/签名无效
- 资源中嵌入 PE/脚本

### 3.3 加壳与混淆

- UPX、Themida、VMProtect 等
- 高熵
- 节名异常
- 导入表极小
- 字符串加密

处理：

- 识别壳类型
- 脱壳（仅授权/学习）
- 动态分析绕过

### 3.4 字符串

关注：

- URL、IP、域名
- 文件路径
- 注册表键
- 服务名
- 命令
- 互斥体（Mutex）
- 加密/编码字符串
- 错误信息
- 家族特征

## 4. 动态分析

### 4.1 沙箱

在线：

- Any.Run
- Hybrid Analysis
- Joe Sandbox
- VirusTotal 行为报告
- 微步在线沙箱

本地：

- Cuckoo（较旧）
- CAPE
- Speakeasy

> 上传前确认样本不含企业敏感信息。

### 4.2 监控工具

| 工具 | 用途 |
|---|---|
| Procmon | 文件/注册表/网络/进程 |
| Process Hacker | 进程、内存、网络、模块 |
| Process Explorer | 进程树、句柄、签名 |
| API Monitor | API 调用 |
| Regshot | 注册表快照对比 |
| Wireshark | 网络流量 |
| FakeNet-NG | 模拟网络 |
| INetSim | 模拟服务 |
| x64dbg | 调试 |
| Sysmon | 行为日志 |

### 4.3 观察什么

- 进程创建/子进程
- 文件落地/修改/删除
- 注册表修改
- 服务/计划任务
- 网络连接/DNS/HTTP
- 凭据访问
- 持久化
- 反调试/反沙箱
- 加密/勒索行为
- 横向

## 5. IOC 提取

| 类型 | 示例 |
|---|---|
| 文件哈希 | SHA256 |
| 文件名/路径 | `%AppData%\...` |
| 注册表 | Run、Services |
| 服务名 | 随机字符串 |
| 互斥体 | 家族特征 |
| 网络 | IP、域名、URL、端口 |
| 证书 | 自签名、主题 |
| JA3/JA3S | C2 指纹 |
| YARA | 样本规则 |
| 行为 | TTP |

> IOC 要标注置信度、来源、时间、上下文。

## 6. YARA 规则

```yara
rule Example_Malware
{
    meta:
        author = "blue-team-lab"
        description = "Example rule"
        date = "2026-11-09"
        hash = "sha256..."
    strings:
        $s1 = "malicious.example.com" ascii wide
        $s2 = "Global\\ExampleMutex" ascii wide
        $h1 = { 4D 5A 90 00 }
    condition:
        uint16(0) == 0x5A4D and
        filesize < 5MB and
        2 of ($s*)
}
```

最佳实践：

- 明确目标和范围
- 使用独特字符串
- 避免过短/通用字符串
- 使用 `ascii wide`
- 限制文件大小
- 测试误报
- 版本管理

## 7. 家族判断

依据：

- 字符串/互斥体
- 网络特征
- 加密算法
- 持久化方式
- 代码相似性
- 情报匹配
- 沙箱标签

> 家族判断不是目的，**行为与检测**才是目的。不要因家族标签而忽略实际行为。

---

## 8. 清除与查杀

1. 隔离主机。
2. 保存样本与证据。
3. 识别持久化并清除。
4. 删除恶意文件（先备份）。
5. 修复入口。
6. 重置凭据。
7. 全盘扫描。
8. 恢复/重装。
9. 监控复发。
10. 更新检测规则。

> 仅删除文件通常不够，持久化与凭据必须处理。

## 10. 实操

1. 在隔离环境分析一个公开教育样本。
2. 计算哈希并在 VT 查询（注意隐私）。
3. 用 strings 提取 URL/域名。
4. 用 PE-bear 查看节区与导入表。
5. 用 Procmon 观察文件/注册表行为。
6. 用 Wireshark/FakeNet 观察网络。
7. 写 YARA 规则并测试。
8. 写分析报告。

> 仅使用公开样本或自己构造的无害测试文件。
