## 1. 什么是安全基线

安全基线是一组**最低安全配置要求**，用于降低攻击面、满足合规、提升一致性。

基线来源：

- 等级保护 2.0（GB/T 22239-2019）
- CIS Benchmarks
- DISA STIG
- Microsoft Security Baselines
- 厂商最佳实践
- 企业内部标准

> 基线不是「越严越好」，要在安全、业务、可用性之间平衡。

---

## 2. 加固流程

```text
资产梳理 → 选择基线 → 差异评估 → 测试 → 灰度 → 推广
→ 验证 → 例外管理 → 持续监控 → 定期复审
```

关键：

- 先备份/快照
- 先在测试环境验证
- 分批实施
- 记录变更
- 有回滚方案
- 业务部门确认
- 例外有期限与补偿控制

## 3. Windows 加固

### 3.1 账号与认证

- 禁用默认 Administrator（或改名）
- 禁用 Guest
- 强密码策略
- 账户锁定策略
- 限制本地管理员
- LAPS 管理本地管理员密码
- 启用 MFA（远程/特权）
- 服务账号最小权限
- 定期审计账号

```powershell
net user guest /active:no
net accounts
Get-LocalGroupMember -Group "Administrators"
```

### 3.2 补丁与软件

- 及时打补丁
- 卸载不必要软件
- 禁用不必要服务
- 应用白名单（WDAC/AppLocker）
- 软件来源控制

### 3.3 网络与远程

- 启用防火墙
- 限制 RDP 来源
- 启用 NLA
- 禁用 SMBv1
- 禁用 LLMNR/NBT-NS（如可行）
- 限制 WinRM
- 禁用不必要共享

```powershell
Set-SmbServerConfiguration -EnableSMB1Protocol $false
Get-SmbServerConfiguration | Select EnableSMB1Protocol
```

### 3.4 审核与日志

- 开启关键审核
- 进程创建命令行
- PowerShell 脚本块日志
- Sysmon
- 日志集中
- 日志保留

### 3.5 凭据保护

- Credential Guard
- LSA Protection（RunAsPPL）
- 限制 NTLM
- 禁用 WDigest 明文缓存
- 保护 SAM
- 特权账号分层

### 3.6 攻击面减少

- 禁用宏（或限制）
- 禁用不必要浏览器扩展
- 限制 USB
- 启用 Defender/ASR
- 禁用旧协议
- 关闭不必要端口

### 3.7 组策略/本地策略

- 密码策略
- 锁定策略
- 审核策略
- 用户权限分配
- 安全选项
- 软件限制

## 4. Linux 加固

### 4.1 账号与认证

- 禁止 root 远程登录
- 使用密钥登录
- 强密码
- sudo 最小权限
- 禁用不必要账号
- 锁定失败次数（fail2ban）
- MFA（如可行）

```bash
# /etc/ssh/sshd_config
PermitRootLogin no
PasswordAuthentication no
PubkeyAuthentication yes
MaxAuthTries 3
```

> 修改前先确认密钥登录可用，并保留一个已登录会话，避免把自己锁在服务器外。

### 4.2 补丁与软件

- 及时更新
- 最小化安装
- 移除不必要服务
- 使用可信源
- 校验软件签名/哈希

### 4.3 权限与文件

- 关键文件权限
- 禁止 world-writable
- 限制 SUID/SGID
- 检查 capabilities
- 保护 `/etc/passwd`、`/etc/shadow`、`/etc/sudoers`

```bash
chmod 644 /etc/passwd
chown root:shadow /etc/shadow
chmod 640 /etc/shadow   # 以发行版基线为准（常见 640 root:shadow 或 000 root:root）
chmod 440 /etc/sudoers
```

### 4.4 服务与网络

- 关闭不必要服务
- 防火墙（iptables/nftables/firewalld/ufw）
- 限制监听地址
- 禁用 IPv6（如不需要）
- SSH 限制来源

### 4.5 内核与访问控制

- SELinux/AppArmor
- 内核参数加固（`/etc/sysctl.conf`）
- 禁用 core dump（含敏感信息）
- 限制 ptrace
- 启用 auditd

```bash
# 示例：限制 ptrace
kernel.yama.ptrace_scope = 1
```

### 4.6 日志与审计

- rsyslog/journald 集中
- auditd 规则
- 日志权限
- 时间同步
- 日志轮转

## 11. 常见误区

- 直接套用高安全基线导致业务故障
- 不测试就全量推广
- 没有回滚方案
- 只做一次，不持续
- 不记录例外
- 只关注主机，忽略网络/云
- 认为加固等于打补丁
- 忽视日志与监控

---

## 12. 实操

1. 用 Lynis 扫描 Ubuntu，阅读建议。
2. 用 Microsoft Security Compliance Toolkit 对比 Windows 基线。
3. 禁用 SMBv1，验证。
4. 配置 SSH 密钥登录并禁用密码。
5. 配置 auditd 监控关键文件。
6. 用 OpenSCAP 扫描一台虚拟机。
7. 编写一份基线核查表与整改计划。
