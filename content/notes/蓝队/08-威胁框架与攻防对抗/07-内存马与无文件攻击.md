## 1. 什么是内存马

内存马（Memory Shell）是不落地文件、驻留在 Web 容器/JVM/进程内存中的恶意组件，访问时执行命令或回连。

优势（攻击者视角）：

- 不写文件，绕过文件查杀
- 重启前持续有效
- 难以通过文件完整性发现
- 可伪装正常请求

蓝队需要理解其形态，才能从**流量、内存、行为**发现。

## 2. 常见类型

### 2.1 Java

| 类型 | 说明 |
|---|---|
| Servlet | 注册恶意 Servlet |
| Filter | 注册恶意 Filter |
| Listener | 注册恶意 Listener |
| Agent | Java Agent 动态修改字节码 |
| Valve | Tomcat Valve |
| 框架组件 | Spring/Tomcat 等 |

常见容器：Tomcat、WebLogic、Jetty、Spring Boot、JBoss。

### 2.2 PHP

- 扩展/模块
- 运行时钩子
- OPcache 滥用
- 说明：`auto_prepend_file`、`.user.ini` 需要落地文件，属于文件型后门/配置型持久化，不是纯内存马。

### 2.3 .NET

- IIS Module
- HttpModule
- 动态编译
- 内存加载程序集

### 2.4 其他

- 反序列化链注入
- 表达式注入
- Web 框架中间件

## 3. 无文件攻击

不落地可执行文件的攻击方式：

| 技术 | 说明 |
|---|---|
| PowerShell | 下载执行、编码命令 |
| WMI | 远程执行、事件订阅 |
| mshta | 执行 HTA/VBScript |
| rundll32 | 执行 DLL 导出 |
| regsvr32 | 执行 COM 脚本（Squiblydoo） |
| certutil | 下载/解码 |
| bitsadmin | 下载 |
| msiexec | 执行 MSI |
| installutil | 执行 .NET |
| csc | 编译执行 |
| wmic | 执行命令 |
| 计划任务 | 触发脚本 |
| 注册表 | 存储载荷 |
| 进程注入 | 内存执行 |
| 浏览器/Office | 宏、脚本 |

> 这些是「合法系统工具被滥用」（LOLBAS），单纯看文件名无法判断。

## 4. 检测：内存马

### 4.1 流量

- 固定 URL/参数访问
- 响应内容异常（命令输出、Base64）
- 请求/响应长度固定
- 非业务时间访问
- 访问不存在的路由却返回 200
- 同一 URI 高频
- UA/Cookie 异常
- 与正常业务响应差异

### 4.2 主机/内存

- Web 进程异常模块/类
- JVM 中异常 Servlet/Filter/Listener
- 动态注册组件
- 异常 Agent
- 内存中的恶意代码
- Web 进程拉起 shell

工具：

- Arthas（阿里开源 JVM 诊断）
- copagent（Java 内存马检测）
- java-memshell-scanner
- EDR 内存扫描
- Volatility（内存取证）

> 工具使用要在授权环境，避免影响生产 JVM。

### 4.3 日志

- Web 访问日志异常
- 容器日志
- 类加载/Agent 日志
- 异常错误

### 4.4 检测思路

1. 确认 Web 容器与框架。
2. 检查近期部署/变更。
3. 检查异常请求模式。
4. 检查 JVM 组件注册。
5. 检查内存/类加载。
6. 检查 Web 进程行为。
7. 保存证据，重启验证（谨慎）。

## 5. 检测：无文件

### 5.1 日志与遥测

- 4688 命令行（含编码/下载）
- PowerShell 4104
- Sysmon 1/3/7/8/10/11/13/22
- WMI-Activity
- 计划任务 4698
- 注册表 13
- EDR 行为

### 5.2 可疑命令行

- `powershell -enc`
- `IEX`、`DownloadString`
- `mshta http://`
- `rundll32 javascript:`
- `regsvr32 /s /u /i:http://`
- `certutil -urlcache -f`
- `bitsadmin /transfer`
- `wmic process call create`
- `msiexec /i http://`

> 这些命令也可能是正常运维，需要结合父进程、用户、网络、时间判断。

### 5.3 进程行为

- Office/浏览器 → 脚本宿主
- `wmiprvse.exe` → 子进程
- `rundll32`/`regsvr32` 外连
- 进程注入（Sysmon 8/10）
- 异常模块加载

### 5.4 网络

- 脚本进程外连
- 下载可执行文件
- C2 心跳
- DNS 查询

### 6.3 网络

- 出站限制
- 代理
- DNS 监控

### 6.4 监控

- 内存马检测

- 脚本下载

## 7. 应急响应

1. 隔离主机/下线应用。
2. 保存内存、进程、Web 日志、流量。
3. 确认内存马/无文件载荷。
4. 分析入口（反序列化/上传/表达式注入）。
5. 检查持久化、账号、横向。
6. 重启/重建应用（内存马重启可能消失，但入口仍在）。
7. 修复入口。
8. 恢复并监控。
9. 复盘与规则更新。

> 仅重启不一定清除内存马，必须修复入口并检查是否再次植入。

---

## 8. 实操

1. 在本地 Java 实验环境用 Arthas 查看 Servlet/Filter。
2. 用 copagent 扫描测试环境。
3. 分析一段 PowerShell 编码命令。
4. 用 Sysmon 观察 `mshta`/`rundll32` 行为。
5. 写一条检测规则：Office → mshta。
6. 用 Wireshark 分析内存马流量（公开样本）。
7. 阅读一次内存马应急报告。

> 仅限本地/授权环境。
