## 1. 为什么需要实验环境

蓝队技能必须动手验证：

- 学日志，需要自己产生登录失败、进程创建、服务安装等事件。
- 学流量，需要自己抓包、构造异常流量。
- 学应急，需要一台「被入侵」的虚拟机让你排查。
- 学恶意样本，需要隔离环境防止感染宿主机。

**核心原则：攻击机、受害机、分析机分离；能快照就快照；能断网就断网。**

## 2. 硬件与软件准备

### 2.1 硬件建议

| 配置 | 最低 | 推荐 | 说明 |
|---|---|---|---|
| CPU | 4 核 | 8 核及以上 | 同时开 2-4 台虚拟机 |
| 内存 | 8 GB | 16-32 GB | Windows 虚拟机很吃内存 |
| 硬盘 | 100 GB 空闲 | 256 GB SSD 以上 | 镜像、快照、日志很占空间 |
| 网络 | 普通宽带 | 可桥接/可 NAT | 部分实验需要桥接 |

> 内存不足时，优先开 Linux 轻量虚拟机；Windows 分析机用完即关，不要长期挂着。

### 2.2 虚拟化软件

| 软件 | 优点 | 缺点 | 适用 |
|---|---|---|---|
| VMware Workstation Pro | 稳定、快照强、网络配置清晰 | 个人使用免费（以官方最新政策为准） | 推荐 |
| VMware Workstation Player | 已停止提供，不建议新装 | 功能较少 | 备选 |
| Oracle VirtualBox | 免费开源 | 性能和兼容性略逊 | 备选 |
| Hyper-V | Windows 自带 | 网络配置稍复杂，可能与 VMware 冲突 | Windows 用户 |
| Proxmox VE | 适合搭建家庭实验室服务器 | 需要独立机器 | 进阶 |

> 不要在已开启 Hyper-V 的机器上同时使用 VMware 的部分功能，可能出现冲突。二选一或按官方说明配置。

### 2.3 必备镜像

| 镜像 | 用途 | 获取方式 |
|---|---|---|
| Kali Linux | 攻击机（用于理解攻击、验证检测） | https://www.kali.org/get-kali/ |
| Ubuntu Server LTS | Linux 受害机/日志服务器 | https://ubuntu.com/download/server |
| Ubuntu Desktop LTS | 日常 Linux 学习 | https://ubuntu.com/download/desktop |
| Windows 10/11 | Windows 受害机 | Microsoft 官方评估版/合法授权 |
| Windows Server 2019/2022 Evaluation | AD、日志、服务实验 | https://www.microsoft.com/en-us/evalcenter/ |
| Metasploitable 2/3 | 经典漏洞靶机 | 官方/社区镜像 |
| DVWA | Web 漏洞练习 | https://github.com/digininja/DVWA |
| Vulhub | 漏洞复现环境 | https://vulhub.org/ |
| REMnux | 恶意样本分析 | https://remnux.org/ |
| Flare VM | Windows 恶意样本分析 | https://github.com/mandiant/flare-vm |

> 只从官方或可信来源下载镜像；不要下载来源不明的「精简版」「破解版」系统。

## 3. 网络规划

### 3.1 三种常见网络模式

| 模式 | 说明 | 用途 |
|---|---|---|
| NAT | 虚拟机通过宿主机上网，外部不能主动访问 | 日常学习、更新 |
| Host-Only / 仅主机 | 虚拟机与宿主机互通，不能上外网 | 隔离实验 |
| 桥接 | 虚拟机与宿主机同网段，可被局域网访问 | 模拟真实网络 |
| 内部网络（Internal） | 仅虚拟机之间互通 | 恶意样本、靶场隔离 |

### 3.2 推荐拓扑

```text
                    ┌─────────────────────┐
                    │  宿主机（Host）      │
                    │  浏览器 / 笔记 / 工具 │
                    └──────────┬──────────┘
                               │ Host-Only
              ┌────────────────┼────────────────┐
              │                │                │
      ┌───────▼──────┐ ┌───────▼──────┐ ┌──────▼───────┐
      │ Kali 攻击机   │ │ Ubuntu 受害机 │ │ Windows 受害机│
      │ 10.10.10.10  │ │ 10.10.10.20  │ │ 10.10.10.30  │
      └──────────────┘ └──────────────┘ └──────────────┘
                               │
                    ┌──────────▼──────────┐
                    │ 日志/SIEM/Wazuh 服务器 │
                    │ 10.10.10.40          │
                    └─────────────────────┘
```

### 3.3 快照策略

在以下节点打快照：

1. 系统安装完成、更新完成、工具装好。
2. 实验开始前。
3. 恶意样本分析前。
4. 靶场通关后（保留环境）。

命名规范：`clean-base`、`before-malware`、`after-exploit`。

## 4. 工具清单

### 4.1 基础分析工具

| 类别 | 工具 | 用途 |
|---|---|---|
| 抓包 | Wireshark、tshark、tcpdump | 流量分析 |
| 网络 | Nmap、Netcat、curl、dig、nslookup | 连接与探测 |
| Windows | Sysinternals Suite（Process Explorer、Procmon、Autoruns、TCPView） | 主机排查 |
| Windows 日志 | Event Viewer、EvtxECmd、Chainsaw、Hayabusa、DeepBlueCLI | 事件日志分析 |
| Linux | journalctl、ausearch、aureport、lsof、ss、netstat | 主机排查 |
| 终端 | Velociraptor、osquery、Wazuh Agent | 资产与行为采集 |
| 内存 | Volatility 3、MemProcFS | 内存取证 |
| 磁盘 | FTK Imager、Autopsy、The Sleuth Kit | 磁盘取证 |
| 时间线 | plaso/log2timeline、Timesketch | 时间线分析 |
| 样本 | strings、PE-bear、Detect It Easy、x64dbg、Procmon | 静态/动态分析 |
| 规则 | YARA、Sigma、Suricata、Snort | 检测规则 |
| 编码 | CyberChef | 编码/解码/转换 |
| 情报 | VirusTotal、OTX、ThreatFox、MalwareBazaar | 样本与 IOC 查询 |

> 工具下载务必走官方渠道。Sysinternals 已并入 Microsoft Learn。

### 4.2 SIEM/日志平台

| 方案 | 适合 | 说明 |
|---|---|---|
| Wazuh | 入门、单机 | 开源，集成 HIDS、日志、规则 |
| Security Onion | 网络监控与 NSM | 集成 Zeek、Suricata、Arkime、Elastic |
| Elastic Stack（ELK） | 日志分析 | Elasticsearch + Logstash + Kibana |

| 商用 SIEM | 企业环境 | 奇安信、深信服、绿盟、IBM QRadar、ArcSight 等 |

## 5. 日志实验环境（重点）

### 5.1 最小可用方案

```text
Windows 受害机
  ├─ 开启审核策略（登录、进程创建、服务、计划任务）
  ├─ 安装 Sysmon（使用社区配置）
  └─ 安装 Wazuh Agent 或 Winlogbeat

Ubuntu 日志服务器
  ├─ 安装 Wazuh Manager / Elastic Stack
  ├─ 接收 Windows 与 Linux 日志
  └─ 配置告警与仪表盘
```

### 5.2 Windows 审核策略建议

用管理员 PowerShell 执行（实验环境）：

```powershell
auditpol /set /subcategory:"登录" /success:enable /failure:enable
auditpol /set /subcategory:"进程创建" /success:enable
auditpol /set /subcategory:"安全系统扩展" /success:enable /failure:enable
auditpol /set /subcategory:"其他对象访问事件" /success:enable /failure:enable
auditpol /set /subcategory:"用户账户管理" /success:enable /failure:enable
```

> 以上为中文系统常见名称；不同版本可能略有差异，建议用 `auditpol /list /subcategory:*` 查看，或使用英文系统做实验。对应关系：4697 → 安全系统扩展；4698-4702 → 其他对象访问事件。

同时开启命令行记录：

```text
计算机配置 → 管理模板 → 系统 → 审核进程创建
→ 启用「审核进程创建」并勾选「包含命令行」
```

### 5.3 Sysmon 安装

```powershell
# 下载 Sysmon 与配置后，以管理员运行
Sysmon64.exe -accepteula -i sysmonconfig.xml
```

常用配置：

- SwiftOnSecurity：https://github.com/SwiftOnSecurity/sysmon-config
- Olaf Hartong Modular：https://github.com/olafhartong/sysmon-modular

### 5.4 用 Kali 产生攻击日志

```bash
# SSH 爆破（仅对实验机）
hydra -l test -P /usr/share/wordlists/rockyou.txt ssh://10.10.10.20

# Web 扫描
nikto -h http://10.10.10.20

# 目录爆破
ffuf -u http://10.10.10.20/FUZZ -w /usr/share/wordlists/dirb/common.txt
```

然后在 Windows/Linux 受害机与 SIEM 中观察日志。

## 6. 恶意样本分析环境

### 6.1 原则

1. **物理或逻辑隔离**：内部网络，不与宿主机共享文件夹，不使用桥接。
2. **禁用共享剪贴板、拖拽、共享文件夹**。
3. **快照后再运行样本**。
4. **不要在宿主机直接运行样本**。
5. **样本压缩加密保存**，避免误杀与扩散。
6. **遵守法律与企业规定**，不传播样本。

### 6.2 推荐组合

| 角色 | 系统 | 工具 |
|---|---|---|
| 分析机 | REMnux / Ubuntu | strings、YARA、CyberChef、Volatility |
| 受害机 | Windows 10 + Flare VM | Procmon、Process Explorer、x64dbg、Wireshark |
| 网络 | INetSim / FakeNet-NG | 模拟 DNS/HTTP，观察 C2 行为 |
| 沙箱 | 在线沙箱 | Any.Run、Hybrid Analysis、Joe Sandbox |

### 6.3 在线沙箱注意事项

- 不要上传含企业敏感信息、个人信息、未公开漏洞的样本。
- 公开沙箱的报告可能被他人看到。
- 先本地静态分析，确认无敏感信息再上传。

## 8. 常见问题

### Q1：内存不够怎么办？

- 减少同时运行的虚拟机数量。
- 使用 Ubuntu Server 无桌面版。
- 用 Docker 跑 Vulhub，减少整机开销。
- 用在线靶场替代部分本地靶场。

### Q2：虚拟机无法上网？

- 检查网络模式是否为 NAT。
- 检查虚拟网卡是否启用。
- 检查 DNS 配置。
- 检查宿主机代理/防火墙。

### Q3：Windows 评估版过期？

- 实验环境可重建快照。
- 使用合法授权的系统。
- 不要使用来源不明的激活工具。

### Q4：SIEM 太重跑不动？

- 先用 Wazuh 单机版。
- 用 Splunk Free 或 Elastic 单节点。
- 只接入关键日志，减少数据量。
