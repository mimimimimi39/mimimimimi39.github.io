## 1. 文件上传漏洞

### 1.1 原理

应用允许用户上传文件，但校验不足，攻击者上传可执行脚本（Webshell）、恶意文件或超大文件。

常见后果：

- Webshell 远程控制
- 服务器被入侵
- 恶意文件托管/钓鱼
- 拒绝服务（大文件）
- 客户端攻击（恶意文档）

### 1.2 常见校验与绕过思路（防御视角）

| 校验 | 绕过思路（概念） | 防御 |
|---|---|---|
| 前端 JS 校验 | 绕过前端直接发包 | 服务端必须校验 |
| 扩展名黑名单 | 大小写、双扩展名、特殊后缀 | 白名单 + 解析配置 |
| MIME 类型 | 篡改 Content-Type | 校验文件内容 |
| 文件头/魔数 | 伪造文件头 | 深度检测 + 重命名 |
| 路径限制 | 路径穿越 | 规范化路径 + 固定目录 |
| 内容检测 | 混淆/加密 | 沙箱/AV/YARA + 权限隔离 |
| 解析漏洞 | 特定中间件配置 | 正确配置 + 禁止脚本执行 |

> 这里只讲防御视角，不提供可直接利用的 payload。

### 1.3 检测线索

**Web 日志**：

- `POST` 到上传接口
- `multipart/form-data`
- 文件名含 `.php`、`.jsp`、`.aspx`、`.phtml`、`.jspx`
- 文件名含 `%00`、`..`、双扩展名
- 上传后紧跟对上传文件的访问（尤其是 POST）
- 上传目录出现异常请求
- 响应 200 且返回路径

**主机**：

- Web 目录新增脚本文件
- 文件创建事件（Sysmon 11）
- Web 进程拉起 shell（`w3wp.exe` → `cmd.exe`）
- 上传目录权限过大
- 文件内容含 `eval`、`system`、`base64_decode`

**流量**：

- 上传请求体含脚本代码
- 上传后访问 Webshell 的请求
- 编码/加密的 POST 数据

### 1.4 防御

- 扩展名白名单
- 校验 MIME 与文件内容
- 重命名文件（随机名）
- 存储到 Web 根目录之外
- 上传目录禁止执行脚本
- 限制文件大小与类型
- 图片重新编码
- AV/YARA 扫描
- 最小权限运行 Web 服务
- 隔离上传域（独立域名/存储）

## 2. 命令注入

### 2.1 原理

应用把用户输入拼接到系统命令中。

```python
# 错误示例
os.system("ping -c 1 " + user_input)
```

输入 `127.0.0.1; whoami` 后执行两条命令。

### 2.2 常见拼接符

| 符号 | 作用 |
|---|---|
| `;` | 顺序执行 |
| 竖线 | 管道 |
| 双竖线 | 前者失败则执行后者 |
| `&&` | 前者成功则执行后者 |
| `&` | Unix：后台执行；Windows cmd：顺序分隔；PowerShell：调用运算符 |
| `` `cmd` `` | 命令替换 |
| `$(cmd)` | 命令替换 |
| `%0a` | 换行 |

> Windows 与 Linux 的符号支持略有差异。

### 2.3 盲命令注入

无回显时，攻击者可能使用：

- 时间延迟（`sleep`、`ping`）
- 外带（DNS/HTTP）
- 写文件到 Web 目录
- 反弹 shell

**检测**：响应时间异常、外连、异常文件创建。

### 2.4 检测线索

**Web 日志**：

- 参数含 `;`、`|`、`&&`、`$(`、反引号
- 参数含系统命令：`whoami`、`id`、`ipconfig`、`net user`、`cat`、`curl`、`wget`
- 编码形式：`%3B`、`%7C`、`%26`
- 响应时间异常

**主机**：

- Web 进程拉起 `cmd.exe`、`powershell.exe`、`/bin/sh`、`bash`
- 异常子进程链
- 异常网络连接
- 临时目录文件落地

**流量**：

- 外带 DNS/HTTP
- 反弹 shell 连接

### 2.5 防御

- 避免调用 shell（使用安全 API/库）
- 参数化/转义
- 输入白名单（如只允许 IP、数字）
- 最小权限运行
- 容器隔离
- 禁用不必要命令
- 监控子进程

## 3. 上传 + 命令执行组合链

典型 Web 入侵：

```text
漏洞入口（上传/注入/反序列化）
  → 写入 Webshell
  → 访问 Webshell 执行命令
  → 下载工具/提权
  → 持久化
  → 横向移动
  → 数据外传
```

蓝队要按这条链逐环检测：

| 环节 | 检测 |
|---|---|
| 入口 | WAF/Web 日志异常请求 |
| 落地 | 文件创建、Web 目录变更 |
| 执行 | Web 进程子进程、命令日志 |
| 持久化 | 服务、计划任务、启动项 |
| 横向 | 登录、SMB/RDP/WinRM |
| 外传 | 流量、DLP |

## 4. 应急响应

1. 隔离主机/下线 Web 服务（视业务）。
2. 保存 Web 日志、访问日志、上传目录、进程、网络连接。
3. 定位 Webshell/恶意文件，计算哈希。
4. 分析入口（上传/注入/漏洞）。
5. 检查持久化、账号、横向。
6. 清除恶意文件，修复漏洞，重置凭据。
7. 恢复业务并持续监控。
8. 复盘，补充检测规则。

## 5. 实操

在本地 DVWA/靶场：

1. 低难度上传一个测试文件，观察服务端校验。
2. 观察上传目录权限与文件访问日志。
3. 在示例应用中复现命令注入（本地），观察进程树。
4. 用 Sysmon 观察 `w3wp.exe` 子进程。
5. 写一条 WAF 规则拦截异常上传（仅本地）。
6. 用 YARA 写一条 Webshell 检测规则（基础）。

> 禁止对未授权系统测试。
