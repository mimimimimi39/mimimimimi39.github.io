## 1. 安全的目标

### 1.1 CIA 三元组

| 属性 | 含义 | 被破坏的例子 |
|---|---|---|
| 机密性（Confidentiality） | 信息不被未授权访问 | 数据泄露、拖库 |
| 完整性（Integrity） | 信息不被未授权篡改 | 网页篡改、数据篡改 |
| 可用性（Availability） | 授权用户能正常访问 | DDoS、勒索加密 |

### 1.2 扩展属性

- **真实性（Authenticity）**：身份真实可信
- **不可否认性（Non-repudiation）**：行为不可抵赖
- **可追溯性（Accountability）**：操作可审计

### 1.3 AAA

| 缩写 | 含义 | 例子 |
|---|---|---|
| Authentication | 认证：你是谁 | 密码、MFA、证书 |
| Authorization | 授权：你能做什么 | RBAC、ACL |
| Accounting/Auditing | 审计：你做了什么 | 日志、审计 |

## 2. 核心术语

| 术语 | 定义 | 例子 |
|---|---|---|
| 资产（Asset） | 有价值的东西 | 服务器、数据、账号、品牌 |
| 威胁（Threat） | 可能造成损害的来源 | 黑客、恶意软件、内部人员 |
| 脆弱性（Vulnerability） | 可被利用的弱点 | 未打补丁、弱口令、配置错误 |
| 风险（Risk） | 威胁利用脆弱性造成损失的可能性 | 高风险：公网暴露的弱口令数据库 |
| 攻击面（Attack Surface） | 可被攻击的入口总和 | 端口、API、账号、供应链 |
| 事件（Incident） | 已发生或疑似发生的安全事件 | 主机外联 C2、数据泄露 |
| 告警（Alert） | 检测规则触发的提示 | SIEM 规则命中 |
| 误报（False Positive） | 告警但实际无害 | 管理员使用扫描器 |
| 漏报（False Negative） | 有害但未告警 | 未知恶意软件 |

> 风险管理公式（概念上）：`风险 = 威胁 × 脆弱性 × 影响`。蓝队的工作是降低脆弱性、提升检测、缩短响应。

## 3. 安全原则

### 3.1 纵深防御（Defense in Depth）

```text
边界防护（防火墙、WAF、IPS）
  → 身份安全（MFA、最小权限、PAM）
  → 终端安全（EDR、加固、补丁）
  → 应用安全（安全开发、代码审计）
  → 数据安全（加密、脱敏、DLP）
  → 监控响应（SIEM、SOC、IR）
  → 备份恢复（离线备份、演练）
```

单点防御必然失效，要多层互补。

### 3.2 最小权限

- 账号只授予完成工作所需的最小权限
- 服务账号不要用域管
- 数据库账号不要用 root
- 临时权限要回收

### 3.3 职责分离

- 开发、运维、安全相互制衡
- 生产变更需审批
- 敏感操作双人复核

### 3.4 默认安全

- 默认拒绝
- 默认关闭不必要服务
- 默认强密码/MFA
- 默认最小暴露面

### 3.5 零信任（Zero Trust）

核心思想：**永不信任，持续验证**。

- 不以网络位置作为信任依据
- 每次访问都要认证与授权
- 最小权限、微分段
- 持续监控与风险评估

> 零信任不是买一个产品，而是架构与流程的转变。

### 3.6 假设失陷（Assume Breach）

- 假设攻击者已经在内部
- 重点建设检测、隔离、响应能力
- 不依赖单一边界

## 4. 安全框架与合规

### 4.1 NIST 网络安全框架（CSF）

| 功能 | 含义 |
|---|---|
| Govern | 治理：策略、风险、角色 |
| Identify | 识别：资产、风险 |
| Protect | 保护：访问控制、加固、培训 |
| Detect | 检测：监控、告警 |
| Respond | 响应：处置、沟通 |
| Recover | 恢复：恢复、改进 |

> CSF 2.0 增加了 Govern 功能，强调治理。

### 4.2 ISO/IEC 27001

信息安全管理体系（ISMS）国际标准，强调风险管理与持续改进（PDCA）。

### 4.3 等级保护 2.0（中国）

- 标准：GB/T 22239-2019《信息安全技术 网络安全等级保护基本要求》
- 五个安全保护等级，常见二级、三级
- 涵盖安全物理环境、通信网络、区域边界、计算环境、管理中心、管理制度、机构、人员、建设、运维
- 测评流程：定级、备案、建设整改、等级测评、监督检查

### 4.4 中国相关法律

| 法律 | 生效时间 | 关注点 |
|---|---|---|
| 网络安全法 | 2017-06-01 | 网络运行安全、数据保护、日志留存 |
| 数据安全法 | 2021-09-01 | 数据分类分级、重要数据 |
| 个人信息保护法 | 2021-11-01 | 个人信息处理、告知同意 |

> 网络安全法要求采取监测记录技术措施，留存网络日志不少于六个月（具体条款以官方文本为准）。

### 4.5 其他框架

- MITRE ATT&CK：攻击行为知识库
- CIS Controls：18 项关键安全控制
- COBIT：IT 治理
- SOC 2：服务组织控制审计

## 5. 安全体系组成

| 层面 | 目标 | 典型措施 |
|---|---|---|
| 物理安全 | 防物理接触 | 门禁、监控、机柜锁 |
| 网络安全 | 边界与内网隔离 | 防火墙、VLAN、微隔离、IDS |
| 主机安全 | 终端与服务器 | 加固、EDR、补丁、HIDS |
| 应用安全 | 减少漏洞 | SDL、代码审计、WAF、渗透测试 |
| 数据安全 | 防泄露与篡改 | 加密、脱敏、DLP、备份 |
| 身份安全 | 防账号滥用 | MFA、PAM、最小权限、定期审计 |
| 供应链安全 | 防第三方风险 | 供应商评估、SBOM、代码签名 |
| 安全运营 | 持续检测响应 | SOC、SIEM、IR、威胁情报 |
| 合规审计 | 满足监管 | 等保、ISO 27001、内审 |

## 6. 蓝队视角

蓝队是安全体系的「守门员 + 摄像头 + 消防队」：

- **守门员**：边界、终端、身份控制是否有效。
- **摄像头**：日志、流量、告警是否可见。
- **消防队**：事件能否快速遏制、清除、恢复。

### 6.1 蓝队常用指标

| 指标 | 含义 |
|---|---|
| MTTD | 平均检测时间 |
| MTTA | 平均确认时间 |
| MTTR | 平均响应/恢复时间 |
| 告警量 | 每日/每周告警数 |
| 误报率 | 误报数 / 告警数 |
| 覆盖率 | 关键资产/日志/ATT&CK 技术覆盖 |
| 事件复发率 | 同类事件再次发生比例 |

### 6.2 蓝队工作闭环

```text
资产与日志可见 → 检测规则 → 告警 → 研判 → 响应 → 复盘
  → 改进检测/加固/流程 → 再验证
```

---

## 7. 常见误区

- 认为买了安全设备就安全了。
- 认为合规等于安全（合规是底线，不是全部）。
- 只关注外部攻击，忽略内部威胁与供应链。
- 只建设检测，不建设响应。
- 只追求「零事件」，不追求「快速发现与恢复」。
- 把安全当成安全部门一个部门的事。

## 8. 实操

1. 选一个你熟悉的系统，列出它的资产、威胁、脆弱性与风险。
2. 用 CIA 分析一次数据泄露/勒索/DDoS 的影响。
3. 画出该系统的纵深防御层次。
4. 对照等保 2.0 的基本要求，找出 5 个差距。
5. 用一句话解释「合规不等于安全」。
