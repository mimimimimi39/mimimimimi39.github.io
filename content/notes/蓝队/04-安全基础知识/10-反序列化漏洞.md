## 1. 序列化与反序列化

**序列化**：把对象转换为字节流/字符串，便于存储或传输。

**反序列化**：把字节流/字符串还原为对象。

```text
对象 → 序列化 → 字节流 → 存储/传输 → 反序列化 → 对象
```

问题：如果反序列化的数据可控，攻击者可以构造恶意对象，触发危险方法（魔术方法、`readObject`、回调等），实现命令执行、文件操作、SSRF 等。

> 反序列化漏洞的核心不是「反序列化」本身，而是**应用信任了不可信数据，并且类路径中存在可利用的 gadget**。

---

## 2. 常见语言与场景

| 语言/框架 | 机制 | 风险点 |
|---|---|---|
| Java | `ObjectInputStream.readObject` | gadget 链、第三方库 |
| Java | Fastjson `autoType` | 反序列化任意类 |
| Java | Jackson 多态 | 恶意类加载 |
| Java | Shiro `rememberMe` | 反序列化 Cookie |
| Java | WebLogic/Tomcat 等中间件 | 历史漏洞 |
| Java | Log4j2 JNDI | 表达式/JNDI 注入（相关但不同） |
| PHP | `serialize/unserialize` | POP 链、魔术方法 |
| .NET | `BinaryFormatter`、ViewState | 反序列化 |
| Python | `pickle`、`yaml.load` | 任意代码执行 |
| Ruby | `Marshal.load` | 反序列化 |

> Log4j2 的 JNDI 注入严格说是「表达式注入/ JNDI 查找」，常与反序列化一起讨论，因为都能导致远程类加载与命令执行。

## 3. Java 反序列化（概念）

### 3.1 基础流程

```java
ObjectInputStream ois = new ObjectInputStream(input);
Object obj = ois.readObject();  // 触发 readObject
```

攻击者构造的字节流在 `readObject` 时触发 gadget 链。

### 3.2 Gadget 链

gadget 是类路径中可被串联利用的类。常见生态：

- Apache Commons Collections
- Commons BeanUtils
- Spring
- Groovy
- JDK 内置类
- 第三方 JSON 库

> 不展开具体利用代码，蓝队重点是识别特征、日志与修复。

### 3.3 常见入口

- HTTP 请求体（二进制/Base64）
- Cookie（`rememberMe`）
- RMI/JNDI
- JMX
- 消息队列
- 缓存（Redis 序列化对象）
- Session 共享
- 文件上传（序列化文件）

## 4. PHP / .NET / Python

### 4.1 PHP

```php
$obj = unserialize($_GET['data']);
```

魔术方法：`__wakeup`、`__destruct`、`__toString`、`__call` 等可被 POP 链利用。

### 4.2 .NET

- `BinaryFormatter` 极不安全，应禁用
- ViewState 反序列化（需 machineKey）
- `TypeNameHandling` 配置不当的 JSON 库

### 4.3 Python

- `pickle.loads` 可执行任意代码
- `yaml.load`（旧用法）危险，应使用 `safe_load`
- `eval`、`exec` 不要处理不可信输入

## 5. 检测线索

### 5.1 流量与请求

- 请求体为二进制或长 Base64
- Java 序列化魔数：`AC ED 00 05`（十六进制），Base64 常以 `rO0AB` 开头
- `Content-Type: application/x-java-serialized-object`
- Cookie 中的 `rememberMe`
- 异常大的请求体
- 反序列化接口被高频调用
- 请求中出现 `java.`、`com.sun.`、`org.apache.` 等类名
- JNDI/LDAP/RMI 外连（Log4j 场景）

### 5.2 主机与网络

- 应用进程外连 LDAP/RMI/HTTP（加载远程类）
- 应用进程拉起 `cmd.exe`、`bash`
- 临时目录/应用目录出现恶意 class/jar
- 异常 DNS 查询
- 反序列化异常堆栈

### 5.3 日志

- 异常堆栈含 `ClassNotFoundException`、`InvalidClassException`
- WAF 告警
- 应用日志中的反序列化错误
- 访问异常接口

## 6. 防御

### 6.1 根本措施

- **避免反序列化不可信数据**
- 使用 JSON/Protobuf 等简单格式
- 必须使用时，使用类白名单/黑名单
- 升级依赖，修复已知 gadget
- 禁用危险功能（`autoType`、`BinaryFormatter`、危险 JNDI）
- 代码审计与依赖扫描

### 6.2 Java 防护

- 使用 `ObjectInputFilter`（JEP 290）限制类
- 禁用 `ObjectInputStream` 处理外部数据
- Fastjson 关闭 `autoType`，升级到安全版本
- Jackson 禁用多态或使用白名单
- 移除不必要的第三方库
- 更新中间件与 JDK

### 6.3 网络与运行环境

- 应用服务器限制外连（禁止访问 LDAP/RMI/恶意域名）
- 最小权限运行
- 容器隔离
- RASP/WAF 作为补充
- 监控异常类加载与子进程

## 7. 应急响应

1. 确认反序列化入口与请求。
2. 检查应用进程外连、子进程、文件落地。
3. 检查是否加载了恶意 class/jar。
4. 检查凭据、账号、持久化。
5. 保存请求、日志、内存/文件证据。
6. 下线漏洞接口/加 WAF 临时规则。
7. 修复代码/升级组件/禁用危险功能。
8. 复盘并补充检测。

---

## 8. 实操

1. 在本地 Java 示例中体验安全的 JSON 反序列化与不安全的 `ObjectInputStream`（仅学习）。
2. 用 Wireshark 观察 Java 序列化流量特征（魔数）。
3. 用 `ysoserial` 生成测试 payload（仅限本地授权环境），用 WAF/IDS 观察特征。
4. 配置 Jackson/Fastjson 安全选项。
5. 用 `ObjectInputFilter` 限制类。
6. 阅读一次 Log4j 漏洞的检测与修复报告。

> 严禁对未授权系统测试或上传利用工具。
