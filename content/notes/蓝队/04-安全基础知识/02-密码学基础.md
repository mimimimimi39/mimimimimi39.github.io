## 1. 为什么蓝队要学密码学

- 判断「加密」是否真的安全，识别常见误用。
- 理解哈希、签名、证书、TLS，才能分析认证与加密流量。
- 应急时判断数据是否泄露、凭据是否可被破解。
- 识别恶意软件中的编码/加密/混淆。

> 蓝队不需要设计密码算法，但必须知道**什么场景该用什么、什么用法是错的**。

---

## 2. 三个容易混淆的概念

| 概念 | 目的 | 可逆 | 例子 |
|---|---|---|---|
| 编码（Encoding） | 数据格式转换 | 可逆，无密钥 | Base64、URL 编码、Hex |
| 加密（Encryption） | 保密 | 可逆，需密钥 | AES、RSA |
| 哈希（Hashing） | 完整性/指纹 | 不可逆（理论上） | SHA-256、bcrypt |

> **Base64 不是加密**。看到 Base64 不要认为数据已受保护。

---

## 3. 对称加密

加密与解密使用同一密钥。

| 算法 | 状态 | 说明 |
|---|---|---|
| DES | 已淘汰 | 56 位密钥，可暴力破解 |
| 3DES | 逐步淘汰 | 兼容旧系统，性能低 |
| AES-128/192/256 | 推荐 | 分组密码，广泛使用 |
| ChaCha20 | 推荐 | 流密码，移动/无 AES 加速场景 |
| RC4 | 已淘汰 | 存在偏差，协议中禁用 |

### 3.1 分组模式

| 模式 | 特点 | 安全性 |
|---|---|---|
| ECB | 相同明文块产生相同密文块 | 不安全，泄露模式 |
| CBC | 需要 IV，串行 | 需正确使用 IV 与 MAC |
| CTR | 计数器，可并行 | 需唯一 nonce |
| GCM | 认证加密（AEAD） | 推荐 |
| CCM | 认证加密 | 推荐 |

**ECB 的经典问题**：加密图片后仍能看出轮廓。不要使用 ECB。

### 3.2 密钥管理

- 密钥长度足够（AES-128 起步，AES-256 更稳）
- 密钥随机生成
- 密钥不硬编码、不进代码仓库
- 使用 KMS/HSM/密钥管理服务
- 定期轮换
- 分离密钥与数据

## 4. 非对称加密

公钥加密、私钥解密；或私钥签名、公钥验签。

| 算法 | 用途 | 说明 |
|---|---|---|
| RSA | 加密、签名 | 常用 2048/3072/4096 位 |
| ECC | 加密、签名 | 密钥短、性能好 |
| ECDSA | 签名 | TLS 常用 |
| Ed25519 | 签名 | 现代推荐 |
| DH/ECDH | 密钥交换 | 协商会话密钥 |
| DSA | 签名 | 逐步淘汰 |

### 4.1 密钥交换

双方在不安全通道上协商出共享密钥。

- DH（Diffie-Hellman）
- ECDH（椭圆曲线）
- 临时密钥（DHE/ECDHE）提供前向保密

### 4.2 数字签名

```text
签名：私钥 + 消息哈希 → 签名值
验签：公钥 + 消息哈希 + 签名值 → 是否有效
```

提供：

- 完整性
- 身份认证
- 不可否认性

**不提供机密性**（签名不加密消息）。

## 5. 哈希函数

将任意长度输入映射为固定长度输出。

| 算法 | 输出 | 状态 |
|---|---|---|
| MD5 | 128 位 | 已破，不可用于安全 |
| SHA-1 | 160 位 | 已破，不可用于安全 |
| SHA-256 | 256 位 | 推荐 |
| SHA-512 | 512 位 | 推荐 |
| SHA-3 | 可变 | 推荐 |
| BLAKE2/BLAKE3 | 可变 | 快速，推荐场景 |

### 5.1 哈希的用途

- 文件完整性校验
- 密码存储（需加盐 + 慢哈希）
- 数字签名
- 取证与威胁情报（样本哈希）
- 去重

### 5.2 密码存储

**错误做法**：

```text
password → MD5 → 存数据库
```

问题：

- MD5/SHA 太快，可暴力/字典/彩虹表
- 无盐，相同密码哈希相同
- 彩虹表可预计算

**正确做法**：

- 加盐（每个用户唯一随机盐）
- 使用慢哈希：bcrypt、scrypt、Argon2id、PBKDF2
- 调整成本参数
- 密码哈希不可逆，不要「解密」

### 5.3 盐（Salt）

- 随机值，与哈希一起存储
- 防止彩虹表与相同密码碰撞
- 不需要保密，但必须唯一

### 5.4 HMAC

带密钥的哈希，用于消息认证：

```text
HMAC(K, m) = H((K' ⊕ opad) || H((K' ⊕ ipad) || m))
注：K' 为密钥补零/哈希后的块，opad/ipad 为固定填充；Hash(key + message) 不是 HMAC。
```

用途：API 签名、JWT（HS256）、消息完整性。

## 6. PKI 与证书

### 6.1 PKI 组成

- CA（证书颁发机构）
- RA（注册机构）
- 证书库
- CRL/OCSP
- 终端信任库

### 6.2 证书生命周期

```text
申请 → 验证 → 签发 → 使用 → 续期 → 吊销
```

### 6.3 信任链

```text
根 CA（自签名，预置信任）
  └─ 中间 CA
       └─ 服务器证书
```

验证：签名、域名、有效期、吊销状态、用途。

### 6.4 常见问题

- 自签名证书
- 过期
- 域名不匹配
- 弱签名算法（SHA-1）
- 私钥泄露
- 证书链不完整

## 7. TLS 中的密码学

- 密钥交换：ECDHE
- 认证：RSA/ECDSA 证书
- 对称加密：AES-GCM/ChaCha20-Poly1305
- 完整性：AEAD
- 哈希：SHA-256/384
- 密钥派生：HKDF

> 详见 [HTTPS 与 TLS](../02-计算机与网络基础/06-HTTPS与TLS.md)。

## 8. 常见密码学误用

| 误用 | 问题 | 正确做法 |
|---|---|---|
| Base64 当加密 | 无保密性 | 使用 AES/TLS |
| ECB 模式 | 泄露明文模式 | 使用 GCM/CBC+MAC |
| MD5/SHA1 存密码 | 易破解 | bcrypt/Argon2id |
| 无盐哈希 | 彩虹表 | 每用户唯一盐 |
| 硬编码密钥 | 泄露 | KMS/环境变量/密钥管理 |
| 固定 IV/nonce | 重放/泄露 | 随机且唯一 |
| 自制加密算法 | 未经验证 | 使用标准算法 |
| 用 `rand()` 生成密钥 | 可预测 | CSPRNG |
| 签名当加密 | 不提供机密性 | 明确用途 |
| 忽略证书校验 | MITM | 正确校验证书 |
| 过长密钥/低效算法 | 性能问题 | 按标准选择 |

## 9. 常见攻击

| 攻击 | 目标 | 说明 |
|---|---|---|
| 暴力破解 | 口令/密钥 | 尝试所有组合 |
| 字典攻击 | 口令 | 常见密码列表 |
| 彩虹表 | 无盐哈希 | 预计算表 |
| 撞库 | 口令 | 复用泄露密码 |
| 中间人 | 密钥交换/证书 | 劫持或伪造 |
| 降级攻击 | 协议版本 | 强制弱算法 |
| 填充 oracle | CBC | 通过错误信息推断明文 |
| 重放攻击 | 协议 | 重放有效消息 |
| 侧信道 | 实现 | 时间、功耗、缓存 |
| 密钥泄露 | 密钥管理 | 硬编码、仓库泄露 |

> 现代系统更常见的不是「算法被攻破」，而是**实现错误、密钥管理不当、配置错误**。

## 10. 蓝队检测视角

- 证书异常：自签名、过期、域名不匹配、短期证书。
- TLS 配置：旧版本、弱套件、无前向保密。
- 加密流量：JA3/JA3S、SNI、证书、行为。
- 凭据：弱口令、撞库、异常登录。
- 数据保护：敏感数据是否明文传输/存储。
- 恶意样本：编码、加密、混淆、硬编码密钥。
- 密钥泄露：代码仓库、配置文件、日志。

## 11. 实操

```bash
# 哈希
echo -n "hello" | sha256sum
echo -n "hello" | md5sum

# Base64
echo -n "hello" | base64
echo "aGVsbG8=" | base64 -d

# 证书
openssl s_client -connect example.com:443 -servername example.com
openssl x509 -in cert.pem -text -noout

# 文件哈希
certutil -hashfile sample.exe SHA256
Get-FileHash sample.exe -Algorithm SHA256
```

用 CyberChef 练习：Base64、URL 编码、Hex、AES 解密（已知密钥）、哈希。
