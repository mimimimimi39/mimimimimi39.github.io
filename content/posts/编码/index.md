编码题有个很讨厌的特点：不会的时候毫无头绪，会的时候三分钟结束。它不考数学，也不考算法，考的是**认不认得出来**。

我的观点很直接：编码是 CTF 的识字课，必须学，但只需要学到「认得、会解、能套娃」的程度。把 Base 表背下来没有意义，建立「看到这串字符先试什么」的直觉才有用。

这篇是我自己的编码学习方案，包含概念区分、知识地图、分阶段路线、特征速查表和常见坑。

## 先说结论

- 编码不是加密：没有密钥，只有公开规则，知道规则就能还原
- 需要掌握五类：进制与字符集、Base 家族、转义与实体、经典替换、程序化编码
- 工具只需要四样：随波逐流，CyberChef、Python、命令行
- 时间预算：花两天过一遍，之后遇到新花样再补
- 编码只是基础的尝试，不要花太多时间去学习

## 一、先分清编码、加密、哈希

很多人一看到乱码就喊「加密了」，其实大部分时候只是编码。

| 类型 | 有密钥吗 | 可逆吗 | 典型例子 | 在 CTF 里怎么认 |
| --- | --- | --- | --- | --- |
| 编码 | 没有 | 可逆 | Base64、URL 编码、UTF-8 | 规则固定，解出来就是原文 |
| 加密 | 有 | 有密钥才可逆 | AES、RSA、凯撒 | 题面会给密钥、提示或算法 |
| 哈希 | 没有 | 不可逆（部分可爆破） | MD5、SHA-1 | 定长摘要，只能碰撞或查表 |

需要注意：凯撒、ROT13、Atbash 严格说是加密，但经常混在编码题里出现，做题时不用纠结分类，能认出来就行。

## 二、编码知识地图

我把它分成五块，按重要性排序。

### 1. 进制与字符集

这是最底层，也是后面所有东西的基础。

- 二进制、八进制、十进制、十六进制之间的换算
- ASCII：`a` 是 97，`0` 是 48，`A` 是 65
- UTF-8、GBK、UTF-16 的区别，以及乱码是怎么来的
- 字节序（大端/小端）在文件题里的体现

例子：`flag{hello}` 的几种表示

```text
二进制  01100110 01101100 01100001 01100111 ...
八进制  146 154 141 147 173 150 145 154 154 157 175
十六进制 666c61677b68656c6c6f7d
```

注意：进制并不只有二的倍数，也会存在三进制五进制这种，如“flag”的三进制为010210 011000 010121 010211

掌握标准**：能看懂十六进制编辑器，能用 Python 在字符串和字节之间转换，看到乱码知道先换字符集。

### 2. Base 家族

Base 系列是编码题出现频率最高的一类，核心是用一组字符表示二进制数据。

| 名称 | 字符集 | 特征 | 备注 |
| --- | --- | --- | --- |
| Base16 | `0-9A-F` | 就是十六进制 | 常和 Hex 混用 |
| Base32 | `A-Z2-7` + `=` | 大写字母和 2-7，长度是 8 的倍数 | 填充是 `=` |
| Base58 | 去掉 `0OIl+/` 的字母数字 | 没有 `+/=`，常用于比特币 | 无填充 |
| Base62 | `0-9A-Za-z` | 只有字母数字 | 变种多，顺序不固定 |
| Base64 | `A-Za-z0-9+/` + `=` | 大小写混合，末尾可能有 `=` | URL-safe 版本用 `-_` |
| Base85 | ASCII 85 | 符号很多，长度约为原文的 1.25 倍 | Ascii85 是常见变种 |
| Base91 | 91 个可打印字符 | 符号杂乱 | 出现频率低 |
| Base100 | emoji | 一串表情 | 看到 emoji 先试它 |

例子：

```text
原文     flag{hello}
Base64   ZmxhZ3toZWxsb30=
Base32   MZWGCZ33NBSWY3DPPU======
十六进制 666c61677b68656c6c6f7d
```

Base64 的几个细节：

- 标准字符集是 `+` 和 `/`，URL-safe 会换成 `-` 和 `_`
- 长度通常是 4 的倍数，缺的用 `=` 补齐；有的题会故意去掉填充
- 解码结果是字节，不一定是可读文本，可能是压缩包或图片

**掌握标准**：看到一串字符能判断是哪种 Base，会用 Python 或 CyberChef 解开，知道填充和 URL-safe 的坑。

### 3. 转义与实体

这一类是「把字符写成另一种形式」，常见于 Web 和文档。

- URL 编码：`%66%6c%61%67`，空格是 `%20`，双重编码是 `%2566`
- HTML 实体：`&#102;&#108;&#97;&#103;`、`&amp;`、`&lt;`
- JavaScript 转义：`\u0066\u006c\u0061\u0067`、`\x66\x6c\x61\x67`
- JSON/Unicode 转义：`\u4f60\u597d`
- Quoted-printable：`=E4=BD=A0=2C=20`，常见于邮件
- UUencode：以 `begin 644` 开头的文本块

**掌握标准**：能一眼分辨 `%xx`、`&#`、`\u`、`\x`，并且知道它们可以互相嵌套。

### 4. 经典替换

- ROT13：字母位移 13 位，`flag` 变成 `synt`
- ROT47：可打印 ASCII 位移 47 位
- 凯撒密码：位移量不固定，需要爆破 26 种
- Atbash：字母表倒序，`a` 变 `z`
- 词频分析：适用于较长的英文文本

严格地说这些是加密，但在 CTF 里经常以「编码」的面目出现，尤其是和 Base64 套在一起的时候。

**掌握标准**：看到纯字母文本会想到 ROT 和凯撒，能用脚本爆破位移。

### 5. 程序化与隐写式编码

这一类的特点是：编码规则本身是一门「语言」或者一种「伪装」。

- Brainfuck：只有 `+ - < > [ ] . ,` 八种符号
- Ook!：用 Orangutan 单词组成的 Brainfuck 变种
- JSFuck：只用 `[ ] ( ) ! +` 写 JavaScript
- AAEncode / JJEncode：用颜文字或日文符号伪装的 JS
- 零宽字符：用 `U+200B`、`U+200C`、`U+200D`、`U+FEFF` 编码二进制
- 培根密码：用 A/B 两组字符，每 5 位表示一个字母
- 摩斯电码：`.`、`-` 和分隔符，`..-./.-../.-/--.` 是 `FLAG`
- 二维码：数据编码 + 纠错，题目常考损坏、反色、拼接

零宽字符是典型的「看起来什么都没有」：复制出来是空的，但字符数不对。遇到这种题，先把文本转成码点看。

**掌握标准**：看到奇怪符号组合能想到对应的语言，知道零宽字符和摩斯的基本处理方式。

## 三、学习建议

编码的学习非常简单，下好随波，看两遍创建编码的字符串，看到有不认识的编码就直接丢到随波一把梭，只要注意一下密文的格式和是哪个编码解出的即可，在日复一日的解码中自然就会认识部分编码

## 四、看到什么，先试什么

这张表是我做题时的第一反应，建议背下来的是「判断逻辑」，不是工具名。

| 看到的特征 | 可能是什么 | 先试什么 |
| --- | --- | --- |
| `A-Za-z0-9+/`，长度是 4 的倍数 | Base64 | CyberChef / `base64 -d` |
| `A-Z2-7`，以 `=` 结尾 | Base32 | CyberChef |
| 只有 `0-9a-f`，长度为偶数 | 十六进制 | `xxd -r -p` / CyberChef |
| `%xx` 密集出现 | URL 编码 | CyberChef URL Decode |
| `&#...;` 或 `&amp;` | HTML 实体 | CyberChef HTML Entity |
| `\uXXXX` 或 `\xXX` | Unicode / JS 转义 | CyberChef |
| 只有 `.`、`-`、`/`、空格 | 摩斯电码 | 在线解码 / 脚本 |
| 只有 `0` 和 `1` | 二进制 | 按 8 位分组转 ASCII |
| 只有 `0-7` | 八进制 | 转十六进制再转文本 |
| 只有 A/B，长度是 5 的倍数 | 培根密码 | 在线工具 / 脚本 |
| 只有 `+ - < > [ ] . ,` | Brainfuck | 在线解释器 |
| 只有 `[ ] ( ) ! +` | JSFuck | 浏览器控制台 |
| 一串 emoji | Base100 | 在线解码 |
| 看起来是空的，但字符数不对 | 零宽字符 | 转码点分析 |
| 乱码，但字节数正常 | 字符集不匹配 | 换 UTF-8 / GBK / UTF-16 |
| 解完还是另一种编码 | 套娃 | 记录步骤，继续解 |

## 特别说明：简单的解码其实都能随波一把梭，且编码最常见的就是base64，，base64编码末尾的=只是补位作用，可能不会出现，如果在编码头部出现=,可能是base64编码倒序，如果发现大段长编码且尾部出现=，很可能是将图像进行了base64编码



## 五、我的解码流程

1. 随波一把梭
2. 观察特征，看是否倒序或者多重编码
3. 特殊的特征明显的编码直接在线上进行搜索，如兽语，ook，佛曰等

套娃题最怕的是解到一半忘了自己做过什么。我的习惯是每解一层就在笔记里写一行，比如：

```text
原始 -> URL decode -> Base64 decode -> 反转 -> flag
```

## 六、Python 小工具箱

不用装一堆库，标准库就够处理大部分编码。

```python
import base64
import binascii
import urllib.parse

text = "ZmxhZ3toZWxsb30="

# Base64
print(base64.b64decode(text))
print(base64.urlsafe_b64decode(text))

# Base32
print(base64.b32decode("MZWGCZ33NBSWY3DPPU======"))

# 十六进制
print(binascii.unhexlify("666c61677b68656c6c6f7d"))

# URL 编码
print(urllib.parse.unquote("flag%7Bhello%7D"))

# 字节转字符串时注意编码
print(base64.b64decode(text).decode("utf-8"))
```

几个提醒：

- `b64decode` 返回 `bytes`，要 `.decode()` 才是字符串
- 填充缺失时可以手动补 `=`，或者用 `base64.b64decode(text + "=" * (-len(text) % 4))`
- 解码结果不一定是文本，也可能是图片或压缩包，先看文件头
- 字符较大的编码更建议通过脚本进行解码，在线及本地工具容易出现卡死等情况

## 七、常见坑

- **Base64 里有换行**：先去掉空白字符再解
- **Base64 填充被删了**：补 `=` 到 4 的倍数
- **大小写敏感**：Base32 和 Base64 大小写不能混
- **URL 双重编码**：解一次还是 `%xx`，就再解一次
- **十六进制带空格或 `0x` 前缀**：先清理格式
- **GBK 和 UTF-8 混用**：中文乱码大多是这个问题
- **摩斯分隔符不统一**：`/`、空格、换行都可能表示字母间隔
- **零宽字符肉眼不可见**：用 Python 打印 `ord()` 看码点
- **字符串被反转**：解不出来时试试倒序
- **在线工具泄露附件**：比赛文件尽量本地处理

## 九、什么时候该止损

- 一道题卡了 20 到 30 分钟，就去看提示或跳题
- 不要为了一道题写通用爆破脚本，时间成本不划算
- 不要背 Base 字符表，理解特征就够了
- 编码只是 Misc甚至是ctf 的基础必修课，学完就该把时间投给取证和流量

## 结语

编码题的本质是识别，不是计算。你不需要记住所有冷门编码，只需要在看到一个字符串时，能快速判断它属于哪一类、下一步该试什么。

按这份路线走一遍，大概一到两周，之后遇到新花样再查。把省下来的时间拿去做取证和流量，收益会高得多。
